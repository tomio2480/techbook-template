# ISDN 対応 要求・要件

ISDN（国際標準同人誌番号）の申請情報をテンプレート側で保管し，
発行された番号とバーコードを誌面へ反映する仕組みの要求・要件を定める．

## 背景と要求（why）

- 同人誌の作品識別子として [ISDN](https://isdn.jp/) がある．
  書籍の完成後，著者が [申請ページ](https://isdn.jp/mail/registrar/) から
  申請し，運営から番号とバーコード画像をメールで受け取る．
- 申請フォームへ転記する情報（よみがな・レーティング等）が散逸すると，
  申請のたびに集め直しが発生する．テンプレート側で保管場所を定める．
- 受領した番号・バーコードの誌面反映を手作業にすると，
  記載漏れや配置のばらつきが起きる．既存の奥付流し込みと同じく，
  データと体裁を分離して自動反映する．
- 認証情報を Git 管理へ載せない．申請フォームのパスワードは保管しない．

## 用語集（ユビキタス言語）

表 1. ISDN 対応で使う用語．

| 用語 | 意味 |
|---|---|
| ISDN 番号（number） | 発行された 13 桁の番号．プレフィックスは 278〜279 |
| 申請情報（application） | 申請フォームへ転記する下書きデータ．`config/isdn.yaml` に置く．一部は裏表紙の情報ブロックにも使う |
| 情報ブロック | 裏表紙のバーコード画像と文字情報（番号・コード行・発行者）をまとめた領域 |
| コード行 | C コードと価格を「C0095 ¥1000E」形式で併記する行．書籍 JAN コードの慣行に準拠する |
| 発行情報（issued） | 発行後に確定するデータ．番号とバーコード画像パスを持つ |
| バーコード画像 | 運営から受領した画像．`src/assets/isdn-barcode.png` へ置く |
| マーカー | 単独段落として書く置換目印．`{{isdn}}` と `{{isdn-barcode}}` の 2 つ |
| 規定位置 | 裏表紙（表 4）右上．左綴じ本の背を右にした置き方を前提とする |

## 要件（what）

- 申請情報と発行情報を `config/isdn.yaml` に保管する．
  - 申請情報は申請フォームの項目に対応させる．
    大分類・形態・レーティング・発行地域・作品タイトルとよみがな・
    サークル名とよみがな・発行日を持つ．
    C コード・価格・ジャンル・体裁・ページ数・著者・リンクは任意とする．
  - パスワード等の認証情報は保管しない．
    氏名・メールアドレスも既定では保管せず，
    公開リポジトリでの扱いに関する注意をコメントで明示する．
- ビルド時にマーカーを発行情報で置き換える（`scripts/inject-isdn.mjs`）．
  - `{{isdn}}`（`99-colophon.md`）: 番号を単独の段落として出力する．
    位置は正誤表リンクの下・コピーライト表記の直上とする．
  - `{{isdn-barcode}}`（`back-cover.md`）: 情報ブロックを配置する．
    バーコード画像の代替テキストへ「ISDN バーコード（番号）」を入れる．
    - 画像の脇へ文字情報を最大 3 行添える．
      内訳は番号・コード行・発行者（`発行 サークル名` の形式）とする．
    - コード行と発行者は申請情報の `c_code`・`price`・`circle` から引く．
      無い項目の行は出力しない．
    - 形式が 4 桁でない C コードは警告してコード行から外す．
    - 円単位の 0 以上の整数でない価格は警告してコード行から外す．
      数字の抽出で別の価格へ改変する挙動は許さない．
    - 定価の文言（税込・本体＋税など）は流し込まず，
      `back-cover.md` の自由記述に委ねる．頒布形態で表記が割れるためである．
  - データが無い・不正な場合，マーカーを出力から取り除き，
    ビルドログへ警告を出す．出版物へマーカー文字列を残さない．
- テンプレート初期状態では，サンプル発行情報（サンプル番号・
  C コード・価格）とダミーバーコード画像を同梱する．
  - 執筆者が情報ブロックの見た目をビルド直後から確認できるようにする．
  - ダミー画像は実際の読み取りができない旨をコメントで明示する．
  - 発行後は番号・画像とも受領物へ差し替える運用とする．
- 裏表紙ページ（`src/chapters/back-cover.md`）を本文 PDF の
  最終ページとして追加する．バーコードは規定位置へ置く．
  - ISDN 公式にバーコードの配置規定は見当たらないため，
    左綴じ本の表 4 右上を本テンプレートの規定位置とする．
  - 既定値は天 10mm・右端 12mm・幅 40mm とし，
    テーマ CSS の変数（`--isdn-barcode-*`）で調整できるようにする．
  - 情報ブロック内はバーコードを右・文字情報を左に並べる．
    読み上げ順（画像→文字）は DOM 順で保つ．
- 番号の機械検査を行う（`scripts/check-isdn.mjs`・`npm run check:isdn`）．
  - ハイフンを除いて 13 桁の数字であること．
  - プレフィックスが 278 または 279 であること．
  - チェックディジット（モジュラス 10 ウェイト 3・1）が正しいこと．
  - 番号とバーコード画像の片方だけが揃う状態は警告とする．
  - 番号未発行（空値）は正常として扱う．
  - C コード（`application.c_code`）は「C」接頭辞を除いて
    4 桁の数字であること．未設定は正常，違反は警告とする．
  - 価格（`application.price`）は円単位の 0 以上の整数であること．
    桁区切りのカンマは許容する．未設定は正常，違反は警告とする．
  - サンプル番号のまま（差し替え忘れ）のビルドは警告とする．
  - ダミーバーコード画像のままのビルドも警告とする．
    番号と独立に，画像内容のダイジェスト一致で判定する．
  - `npm run build` の冒頭で実行する．

受け入れ条件は次のとおり．

- サンプル番号を設定したビルドで，奥付に番号・裏表紙にバーコードが出る．
- C コード・価格・サークル名を設定したビルドで，バーコード脇に
  コード行と発行者が出る．未設定の項目の行は出力されない．
- 発行情報を空にしてビルドしても，マーカー文字列が PDF に残らない．
  あわせてビルドログに警告が出る．
- 不正な番号（桁数・プレフィックス・チェックディジット違反）を
  `npm run check:isdn` が検出する．
- `npm test` が全件通る．

## スコープ外

- 表紙・裏表紙のデザインテンプレート化（背景画像と文字情報の統合）．
  Issue #58 で別途扱う．本仕様の裏表紙は配置の受け皿となる最小構成とする．
- バーコード画像の自動生成．運営から受領した画像の利用を前提とする．
- 申請メールの自動送信・申請フォームの自動入力．
- 改版時の番号再申請の要否判断と版ごとの番号管理．
