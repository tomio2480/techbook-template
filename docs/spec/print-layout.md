# 紙入稿用 PDF 要求・要件

紙で印刷・製本するための PDF を，電子書籍用の PDF とは別に出力する仕組みの
要求・要件を定める．扉の面を揃える改丁と，綴じの単位へ総ページ数を揃える
面付け，章の位置を示す小口のつめを扱う．
改丁で空くページは白紙にせず MEMO ページで埋める．

## 背景と要求（why）

- 現状の `dist/book.pdf` は電子書籍としてそのまま配布できる状態にある．
  一方，紙で入稿するにはページの並びを製本の都合へ合わせる必要がある．
- 章の扉が見開きの右（奇数ページ）に来ないと，読者は扉を見開きの左で受け取る．
  区分の始まりは面を揃えることで，紙をめくる体験を整える．
- 面を揃えると空くページが生じる．完全な白紙は読者や印刷所から見て
  落丁（ページの抜け）と区別がつかない．意図した余白であると示す必要がある．
- 総ページ数は綴じの単位（用紙 1 枚の表裏で 4 ページ）の倍数でなければ
  入稿できない印刷所が多い．端数の調整を執筆者の手作業に委ねない．
- 紙の本は目次からページ番号を辿るほか，閉じたまま小口を見て目当ての章を
  探す．小口に章の位置を示す帯があれば，読者は本を開かずに見当をつけられる．
- 電子書籍用の見た目は変えない．紙のための調整が電子版へ混ざらないよう，
  出力を分ける．

## 用語集（ユビキタス言語）

表 1. 紙入稿用 PDF で使う用語

| 用語 | 意味 |
|---|---|
| 改丁 | 区分の始まりを指定した面から始めること．空いたページは MEMO ページで埋める |
| 面 | 見開きのどちら側か．`recto` は奇数ページ（開いて右），`verso` は偶数ページ（開いて左） |
| 区分 | まえがき・目次・章・あとがき・奥付など，本を構成するまとまり．エントリ 1 件に対応する |
| 面付け | 総ページ数を綴じの単位（既定 4 ページ）の倍数へ揃えること |
| MEMO ページ | 改丁と面付けで生じるページ．`MEMO` の見出しと枠を持ち，読者が書き込める |
| 調整ページ | 面付けのために入れる MEMO ページ．既定では奥付の直前へ寄せる |
| 小口 | 綴じ側（ノド）の反対側の端．開いて右のページでは紙の右端にあたる |
| つめ | 小口へ刷る章番号の帯と章タイトル．章ごとに高さを変え，章の位置を示す |
| 測定パス | 各区分が何ページになるかを実測するためのビルド．成果物には使わない |
| 本番パス | MEMO ページを入れて組み直す最後のビルド．`dist/book-print.pdf` を出力する |

## 要件（what）

- 紙入稿用 PDF を `npm run build:print` で `dist/book-print.pdf` へ出力する．
  - 電子書籍用の `npm run build`（`dist/book.pdf`）の挙動は変えない．
  - 本文の体裁・行番号・アクセシビリティタグは電子書籍用と同じ経路で作る．
    紙のための差分（改丁・MEMO ページ）だけを重ねる．
- 区分ごとに始まりの面を指定できる．
  - 既定はまえがき・あとがきと章の扉が `recto`，目次・奥付が `verso` とする．
  - 面の指定は `config/book.yaml` の `print.section_start` で行う．
    キーには原稿ファイル名に含まれる文字列を書く．
  - 章扉を持つ原稿の面は `print.chapter_start` で指定する．
    電子書籍用のテーマが持つ章扉の固定指定より，こちらを優先する．
  - 面の指定は `config/book.yaml` を単一の出所とする．
    テーマ CSS には区分の一覧を持たせず，指定の食い違いが起きない形にする．
  - 章扉を持つ原稿かどうかは，原稿中の `chapter-opening` の有無で判定する．
    原稿を改名しても判定が壊れないようにするためである．
- 改丁で空くページには MEMO ページを入れる．白紙のままにしない．
  - `MEMO` の見出しと，版面いっぱいの枠を持つ．
  - ノンブルを残す．通し番号の連続が落丁でない証拠になる．
  - 柱は出さない．直前の章の柱が残ると誤読を招く．
- 総ページ数を綴じの単位の倍数へ揃える．
  - 単位は `config/book.yaml` の `print.page_multiple` で指定する（既定 4）．
  - 不足分は調整ページで埋め，裏表紙を最終ページに保つ．
  - 調整ページは `print.filler_before` が指す区分（既定では奥付）の直前へ寄せる．
    奥付を最後の記載として残し，その後ろへ調整ページが続かないようにする．
  - 寄せ先に面の指定があるときは，面を崩さない偶数ページ分だけを前へ入れる．
    端数の 1 ページは裏表紙の直前（奥付の後ろ）へ残す．
    奥付を偶数ページに固定したまま総ページ数を倍数へ揃えると，
    1 ページだけは奥付の後ろに置かざるを得ないためである．
- 章の位置を示すつめを小口へ刷る．
  - つめは章番号の帯（色ベタ・白抜き）と，その下へ続く章タイトルで構成する．
    どちらも縦組みで小口に沿わせる．
  - 章番号と章タイトルは章の扉の記述（`.chapter-number`・`.chapter-title`）を
    出所とする．扉とつめで表示が食い違わないようにするためである．
    扉を持たない区分では，タイトルを原稿の `h1` から取る．
  - 章番号が数字のときだけ「第 N 章」と組む．付録の `A` などには添えない．
  - 対象は章扉を持つ原稿の本文ページとする．章の判定は改丁と同じく
    原稿中の `chapter-opening` の有無で行う．
  - 章扉を持たない区分にもつめを付けられる．`print.section_tabs` へ
    原稿ファイル名に含まれる文字列と，つめへ刷る番号の文字を並べる．
    番号は扉があれば扉を優先し，無いときだけ指定値を使う．
    面の指定は `print.section_start` が引き続き担い，`section_tabs` は
    面へ影響しない．つめの高さは対象の並び順で決まる．
  - つめは奇数ページ（開いて右）にだけ出す．左右のページへ同じ高さで刷ると，
    紙を透かしたときに重なって見えるためである．
  - 章扉のページには出さない．扉には章番号・章タイトルが大きく出るため，
    つめと重複する．扉は専用のページ（`@page chapter-opening`）で組まれ，
    対象から外れる．そのため，つめを流し込む要素は扉の中へ置く．
  - 高さは章の順に下がる．章の数に応じて，指定した範囲へ均等に散らす．
    章の数は原稿から数え，位置を決める CSS はビルド時に生成する．
  - 大きさ・色・並べる範囲はテーマ CSS の変数（`--tab-*`）で調整する．
- 面付けの結果を機械で検査し，食い違いがあればビルドを失敗させる．
  - 実測から求めた想定ページ数と，組み上がった PDF のページ数を突き合わせる．
  - 総ページ数が指定の倍数へ揃っていることを確かめる．
- MEMO ページの体裁は，他の体裁と同じくテーマ CSS で調整できる．
  - 枠と見出しの配色は `palette.css` の意味トークン（`--memo-*`）で変える．
- 紙入稿用の PDF へ塗り足し（タチキリ）を付ける．
  - 仕上がりより天地左右へ同じ量だけ大きく組む．量は 1 か所で変えられる．
  - 仕上がりの位置を PDF の TrimBox として記録する．
  - 版面の位置と総ページ数は，塗り足しの有無で変わらない．
  - 電子書籍用の PDF へは付けない．読者に余分な余白を見せないためである．
  - 紙面の端に接する要素は塗り足しの端まで広げる．
    対象は表紙・裏表紙の背景と，小口のつめである．
    仕上がり線で止めると，裁ちが外側へずれたときに白い筋が出る．

受け入れ条件は次のとおり．

- `npm run build:print` が `dist/book-print.pdf` を出力し，総ページ数が
  `print.page_multiple` の倍数になる．
- まえがき・あとがき・章の扉が奇数ページから始まり，目次・奥付が
  偶数ページから始まる（既定の指定の場合）．
- 改丁で空いたページと調整ページに `MEMO` の見出しと枠が出る．
- 調整ページが奥付の直前へ入り，奥付の後ろに残るのは多くとも 1 ページである．
- 各章の奇数ページに，章番号と章タイトルを持つつめが章の順で下がって出る．
  章扉・前付・後付・MEMO ページには出ない．
- 章扉の体裁が電子書籍用と揃う．扉には柱とノンブルが出ない．
  つめの流し込みでページ名が変わると，この打ち消しまで失われる．
- `config/book.yaml` の指定を変えると，改丁の面と綴じの単位が変わる．
  `chapter_start` を `verso` にした場合も，テーマ CSS を触らずに組み上がる．
- 紙入稿用の PDF が塗り足しを含む寸法で出力され，TrimBox に仕上がりが入る．
  電子書籍用の PDF は仕上がり寸法のまま変わらない．
- 塗り足しを付けても総ページ数と版面の位置が変わらない．
- 表紙の絵柄がベクターのまま出力され，つめが塗り足しの端まで届く．
- ビルド後の作業ツリーに一時ファイルが残らない．
  対象は MEMO ページの原稿と面付けの計画である．
- ビルド後の追跡ファイルへ紙面用の目印が残らない．
  対象は `src/chapters/toc.html` のように Markdown を持たない原稿である．
  改丁のクラスもつめの記述も，ビルドの後始末で元の中身へ戻す．
- ビルド後に `vivliostyle.config.js` が元の Markdown 参照へ戻る．
- `npm test` と `npm run build` が従来どおり通る．

## スコープ外

- トンボの付与．不要とする印刷所が多く，要件も分かれるためである．
  寸法が正確であれば，印刷所が画像の中心を基準に面付けする．
- つめの体裁の作り分け（章ごとの色替え・帯の形状変更）．
  色と大きさは全章共通の変数で与える．
- 表紙単体の入稿データ生成と背表紙（スパイン）．本仕様は本文 PDF を対象とする．
- 見開き（左右）で異なる余白（ノド・小口）の設定．
- MEMO ページ以外の白紙ページ（章末の端数ページなど）への記載．
- PDF/X への変換や CMYK 化などの印刷所ごとの入稿形式変換．

## 変更記録

- 2026-08-15: 初版作成．改丁で空くページを MEMO ページの挿入で埋める方式は
  Claude の判断による．Vivliostyle は改ページで生じた白ページへ何も描画せず，
  `@page :blank` も効かないため（`@vivliostyle/core` 2.39.0 で確認），
  CSS だけでは白紙を飾れない．各区分のページ数を実測して MEMO ページの
  位置と枚数を決める段取りを採った．
- 2026-08-15: 要件変更．面の指定を `config/book.yaml` 単一の出所へ寄せた．
  テーマ CSS が持っていた区分ごとの改丁指定をやめ，ビルドが伝えるクラスを
  面へ翻訳する形にした．`chapter_start: verso` が電子書籍用テーマの固定指定と
  衝突してビルドできない不具合の指摘（PR #94 のレビュー）による．
- 2026-08-15: 要求追加．小口のつめを要件へ加えた．奇数ページのみへ刷る点と
  章扉を対象外とする点は利用者の指定による．

  章タイトルを刷る形へ変えた．市販書籍の実例に揃える利用者の指定による．

  寄せ先は `print.filler_before` で変えられるようにした．
- 2026-08-17: 受け入れ条件を追加．ビルド後の追跡ファイルへ紙面用の目印を
