# 図版の様式と配色 要求・要件

## 概要

図版 SVG（`src/assets/diagrams/*.svg`）の様式を定める．
対象は配色・図中フォント・検査からの除外の 3 つである．
グレースケール印刷でも色に頼らず読み取れる誌面を，機械検査で守ることをねらう．
本テンプレートおよびこれを用いて作られる派生書籍リポジトリすべてを対象とする．

## 背景と要求（why）

技術同人誌の紙版はグレースケールで刷られることが多い．
色相だけで種別を分けた図は，変換後に手がかりを失う．
電子版と紙版で読み取れる情報が変わる誌面は，教材として成り立たない．

派生書籍リポジトリ
[techbook-introduction-to-electronics-basic-led](https://github.com/tomio2480/techbook-introduction-to-electronics-basic-led)
で，この問題へ実際に対処した．
補助記載の色を変え，多色図 2 点を明度 3 段へ組み替えた．
規約はそのあと機械検査へ昇格させた．
経緯は同リポジトリの
[Issue #178](https://github.com/tomio2480/techbook-introduction-to-electronics-basic-led/issues/178)・
[#180](https://github.com/tomio2480/techbook-introduction-to-electronics-basic-led/issues/180)・
[#182](https://github.com/tomio2480/techbook-introduction-to-electronics-basic-led/issues/182)
にある．
判断の記録は同リポジトリの
`docs/notes/2026-08-05-diagram-annotation-color-grayscale.md` である．
執筆規律としての抽出は `tomio2480/settings` の `techbook-authoring` Skill が担った．

上流のテンプレートには検査だけが移り，閾値の根拠が残らなかった．
検査は `scripts/check-diagram-luminance.mjs` と
`scripts/check-diagram-fonts.mjs` にある．
どちらも定数を持つが，その値を選んだ理由は書かれていない．
派生本で配色を替えるとき，定数へ手を入れてよいかを判断できない
（[Issue #211](https://github.com/tomio2480/techbook-template/issues/211)）．

**価値提案は，図へ色を使ってよいかを目視でなく機械が判定できる状態を保つことである．**
本ごとに色相を替えても，判定の根拠は同じであることを守る．
色相の選択そのものは本の自由とし，本仕様は判別の条件だけを固定する．

## 用語集（ユビキタス言語）

表 1. 図版の様式で使う用語と対応する実装上の識別子

| 用語 | 意味 | 識別子 |
|---|---|---|
| 明度段 | 同じ色相で明度だけを変えた，図版で使ってよい有彩色の並び | `DIAGRAM_TIER_COLORS` |
| 淡い塗り | 面の下地に使う，明度段より明るい色 | `DIAGRAM_WASH_COLORS` |
| 帯 | 明度段が収まるべき Rec.601 輝度の範囲 | `MID_BAND` |
| 輝度差 | 隣り合う明度段の Rec.601 輝度の差 | `MIN_SEPARATION` |
| 補助記載 | 電流・電圧の矢印や電位のラベルなど，回路本体でない書き込み | `--palette-diagram-annotation` |
| 実体色の図 | 実物の色をそのまま再現する図．配色の検査の対象にしない | `check-diagram-luminance.mjs` の `EXCLUDED_FILES` |
| テーマのスタック | 本文と同じゴシック体のフォントスタック | `--font-gothic` |
| 別スタック | 意図して使う，テーマ以外のフォントスタック | `ALLOWED_EXTRA_FONT_STACKS` |
| 読み取れない入力 | 検査が走査の範囲を確定できない，またはブラウザーが XML として読めないマークアップ | `findUnreadableMarkup` |

## 要件（what）

### 配色

- 図版の有彩色は，明度段か淡い塗りに登録した色だけとする．
  登録の無い有彩色は違反として報告する．
- 明度段は同じ色相の 3 段を既定とする．
  色相で種別を分けず，明度で分ける．
  色以外の手がかり（線種・線の太さ・ラベルの位置）を必ず併用する．
- 明度段は帯（Rec.601 輝度で 20〜80 %）へ収める．
  黒い回路本体と白い紙地の双方から判別できる中明度を保つためである．
- 隣り合う明度段の輝度差は 15 ポイント以上とする．
- 淡い塗りは帯の上限を超える明るさとする．
  帯へ入ると明度段と紛れ，線と面をグレースケールで見分けられない．
- 補助記載は基調色と同系の中明度 1 色とする．
  値は `--palette-diagram-annotation` と一致させ，明度段にも含める．
- 回路本体・部品記号・量記号のラベルは無彩色で描く．
  有彩色を補助記載だけに使い，主役と補助を分けるためである．
  無彩色は検査の対象外のため，この要件は機械検査で担保されない．
  同梱サンプルの `led-circuit.svg` も `#333`・`#666` を使う．
- 無彩色は検査の対象にしない．
  種別の判別は線の太さ・線種・文字ラベルが担い，色へ依存させない方針のためである．
- 無彩色の判定は RGB チャンネルの最大と最小の差で行う．
  差が 16 未満なら無彩色とみなす（`CHROMA_THRESHOLD`）．
  紙色系のオフホワイトを無彩色として通すための閾値である．
  淡い塗りの `#f0f4f8` は差が 8 で，この判定では無彩色になる．
  **差が 16 未満の淡い有彩色は，登録しなくても検査を通る．**
  たとえば `#f2efe9` は差が 9 であり，登録なしで通る．
  面の下地に淡い色を使う本は，この境界を踏まえて `DIAGRAM_WASH_COLORS` を決める．
- 色は属性で書く．
  CSS プロパティ形式（`style` 属性・`<style>` 要素）の色指定は違反とする．
- hex へ解釈できない色値は違反とする．
  CSS の名前色や `url()` 参照は，検査のすり抜けを招くため黙認しない．
  例外は `black` と `white` の 2 語に限る．
  無彩色であり明度段への登録を要しないため，hex へ正規化して受け取る．
- 受け入れ条件: `npm test` の `check-diagram-luminance` が違反 0 件で通ること．

### 透明を使わない

- 塗りを透明で薄める形は使わない．
  指定値だけを読む検査が，実際に刷られる色を見逃すためである．
- 合成後の色をあらかじめ焼き，`DIAGRAM_WASH_COLORS` へ登録する．
- `opacity`・`fill-opacity`・`stroke-opacity`・`stop-opacity`・`flood-opacity` の指定は違反とする．
  属性形と CSS 宣言形の双方を対象とする．
  `stop-opacity` を含めるのは，グラデーションの停止色にも同じ盲点があるためである．
  紙入稿では透明効果そのものを外すため，図版の段階で持たせない．
  詳細は `docs/spec/print-layout.md` を参照する．
- 値による場合分けはしない．`opacity="1"` も違反として報告する．
  どこまでを不透明とみなすかの解釈を検査へ持ち込まないためである．
- SMIL による透明化も違反とする．
  `<animate attributeName="opacity" to="0.5"/>` は属性形でも宣言形でもないが，
  描画は半透明になる．透明を禁じた理由がそのまま当てはまる．
- `opacity` 以外で透明を生む指定も違反とする．
  対象は `mask`・`filter`・`mix-blend-mode` である．
  `mask` は灰色の内容でアルファを作り，`filter` は `feFuncA` や
  `flood-opacity` で同じことができる．`mix-blend-mode` は通常でない合成をする．
  いずれも無彩色だけで組めば，配色の検査にも掛からない．
- CSS コメントは宣言として扱わない．
  無効化した旧指定をコメントで残しただけの図は，描画へ影響しないためである．
  対象は `<style>` 要素の中身と `style` 属性の値の双方とする．
  コメントはトークンの境界として扱う．
  取り除くと `opac/*` と `*/ity` が連結し，効かない指定を違反にしてしまう．
- 検査は文書の構造に沿って読む．
  属性はタグの中だけ，CSS の宣言は `<style>` 要素と `style` 属性の値だけを見る．
  図には `title`・`desc` を付けるため，説明文へ宣言と同じ並びが現れうる．
  描画へ影響しない文字列で，適合する図を落とさないためである．
- 除外したファイルは，透明の検査も対象にしない．
  除外は配色検査の `EXCLUDED_FILES` で効き，透明の検査も同じリストに従う．
  フォント検査の除外は別のリストであり，片方へ足しても他方は検査を続ける．
- 受け入れ条件: 半透明で塗った合成 SVG を与えたとき，検査が違反として報告すること．

### 図中フォント

- root の `<svg>` へ `font-family` を書き，値をテーマのスタックと一致させる．
  `img` で埋め込んだ SVG はページの CSS を継承しない．
  指定が無いと図中の和文ラベルはブラウザ既定の書体で描かれ，図ごとにぶれる．
- 子要素には原則としてフォントを書かず，root の値を継承させる．
  書く場合はテーマのスタックか，登録した別スタックに限る．
- 量記号を明朝の斜体で組むなど，意図して使うスタックは
  `ALLOWED_EXTRA_FONT_STACKS` へ登録する．登録の無いスタックは違反とする．
- 書体と大きさは `font-family`・`font-size` へ分けて書く．
  `font` の短縮記法（`font: 20px Courier`・`font="20px Impact"`）は違反とする．
  登録済みのスタックを短縮記法で書いた場合も同じく違反とする．
  短縮記法は値の一部を省略できる．
  書体の部分だけを取り出す解析は誤りやすく，その経路を持たない方針とする．
- `all` の一括指定は違反とする．値による場合分けはしない．
  `all: initial` はほぼ全プロパティを初期値へ戻すため，root の指定が効かなくなる．
  `all: unset` と `all: revert` では，`font-family` が継承プロパティのため root の値が残る．
  挙動は 3 語で違うが，一律に違反とする．
  場合分けは短縮記法で避けた値の解析へ戻るためである．
- root も例外にしない．例外にすると同じ抜け道が root へ残る．
- `font` 属性は Chromium が無視するため誌面の書体は変わらない．
  それでも違反として報告する．指定したつもりの書体が出ない状態を残さないためである．
- 受け入れ条件: `npm test` の `check-diagram-fonts` が違反 0 件で通ること．

### 検査からの除外

- 除外してよいのは実体色の図に限る．
  実物の色をそのまま再現する図は，明度段の対象にしない．
  種別の判別は部品形状とラベルが担う．
- 除外は `EXCLUDED_FILES` へファイル名で書く．
- `EXCLUDED_FILES` は配色検査とフォント検査がそれぞれ別に持つ．
  実体色であることは配色の判断であり，フォントの判断とは別に決める．
  片方へ足しても，もう片方は検査を続ける．
- 実在しない名前が除外に残っていないことを検査する．
  図版を改名すると除外の記載だけが取り残され，検査が素通りするためである．
  この検査は配色検査とフォント検査の双方が持つ．
- 受け入れ条件: 実在しない名前を除外へ残したとき，検査が違反として報告すること．

### 本文の書き方

- 本文は図の要素を色名で指さない．
  たとえば「薄い赤色です」ではなく「回路本体より薄い色です」と書く．
  カラー版とグレースケール版のどちらでも成立する記述にする．

### 読み取れない入力

- 検査は，読み取れない入力を違反として報告する．違反 0 件で通さない．
  検査が壊れているのに合格と報告する状態は，規約の空文化に直結するためである．
- 「読み取れない」は次の 2 つを指す．どちらか一方でも当たれば違反とする．
  - 検査が走査の範囲を確定できない．正規表現でタグや宣言の範囲を取る作りが
    黙って空振りし，違反 0 件で通る．
  - ブラウザーが XML として読めない．図が描画されないまま，
    どの検査も違反 0 件で通る．SVG は XML として読まれるためである．
- 対象とする壊れ方を表 2 に示す．識別子は違反の `kind` である．
  件数を本文へ書かず表で数える．実装へ検出を足したとき，
  本文の数だけが古くなる状態を避けるためである．
- 判定するのは上の 2 つに限る．
  名前空間の解決や属性値の妥当性は，どちらにも当たらないため見ない．
- 判定は共通の部品が担い，各検査はその結果を受け取る．
  検査ごとに持つと，同じ判定が重複したうえ，片方だけ直る状態を生む．
- 読み取れない入力を見つけた図は，その図の他の検査を続けない．
  範囲が確定できない以上，続けた結果は違反の有無を保証しない．
- 除外したファイルは対象にしない．各検査がそれぞれ持つ除外に従う．
- 受け入れ条件: 表 2 の壊れ方をそれぞれ含む合成 SVG を与えたとき，
  検査が違反として報告すること．
  あわせて，作図ツールが書き出す記法を違反にしないこと．

### 機械検査の範囲

本仕様の要件のうち，機械が判定するものと目視に委ねるものを分ける．
`npm test` が通ることは，目視側の要件を満たした証拠にならない．

表 3. 要件ごとの機械検査の有無

| 要件 | 機械検査 | 判定するもの |
|---|---|---|
| 有彩色が明度段か淡い塗りに登録済み | あり | 配色検査 |
| 明度段が帯へ収まる | あり | 配色検査 |
| 隣り合う明度段の輝度差 | あり | 配色検査 |
| 淡い塗りが帯の上限を超える | あり | 配色検査 |
| 補助記載のトークンが明度段にあり使われている | あり | 配色検査 |
| hex へ解釈できない色値 | あり | 配色検査 |
| CSS プロパティ形式の色指定 | あり | 配色検査 |
| 透明の指定（属性・宣言・SMIL・mask・filter・合成モード） | あり | 配色検査 |
| 除外に実在しない名前が残っていない | あり | 配色検査・フォント検査 |
| 読み取れない入力 | あり | 配色検査・フォント検査 |

| 色以外の手がかりを併用している | なし | 目視 |
| 補助記載が 1 色に収まっている | なし | 目視 |
| 回路本体・部品記号・ラベルが無彩色である | なし | 目視 |

目視側が通ってしまう例を挙げる．
色相の違う 3 色を `DIAGRAM_TIER_COLORS` へ登録しても，帯と輝度差さえ満たせば通る．
明度段のうち補助記載でない色を矢印へ使っても通る．
実体色でない図を `EXCLUDED_FILES` へ足しても通る．
いずれも検査は判定材料を持たない．

## 閾値の根拠

数値は派生本での実測に由来する．
根拠を残すのは，派生本が定数へ手を入れてよいかを判断するためである．

**Rec.601 輝度を使う．** 式は Y = 0.299R + 0.587G + 0.114B である．
PDF のグレースケール変換に近い単純輝度であり，紙で起きる変化に対応する．
`scripts/check-contrast.mjs` の WCAG 相対輝度とは意図して別式を使う．
前者は刷り上がりの判別を，後者は画面上の可読性を見るためである．

**帯は 20〜80 % とする．** 黒い回路本体と白い紙地の双方から判別できる中明度を保つ範囲である．
帯を外れた色は，黒か白のどちらかへ寄って沈む．
値そのものは派生本の運用で確かめた経験的な閾値であり，導出の記録は無い．
動かすときは，実際に刷ったグレースケールで判別を確かめる．

**輝度差は 15 ポイント以上とする．**
派生本の明度段は `#2f5b8c`・`#5588bb`・`#8cb2d8` である．
輝度はそれぞれ ≈33 %・≈50 %・≈67 % であり，隣接差は約 17 ポイントである．
閾値はその隣接差の下へ置いた．
実測が裏づけるのは現行配色の約 17 ポイントまでである．
**15 ポイントで判別を保てることは確かめていない．** 導出のない経験的な床である．
差を 15 ポイントまで詰めるときは，刷って判別を確かめる．

**補助記載は 1 色とする．** 派生本では `#5588bb`（輝度 ≈50 %・白地コントラスト比 3.73:1）を選んだ．
基調色と同系の色相を持ち，黒と白のどちらからも離れる中明度だからである．
1 段淡い `#99bbdd`（≈71 %）はビルドの目視で文字が薄く，採らなかった．

**実体色の図を除く．** 実物の色を再現する図では，明度段への置き換えが誤情報になる．
派生本ではブレッドボードの配線図が当たった．
本テンプレートでは同梱サンプルの `led-circuit.svg` が当たる．

## スコープ外

- 色相の選択．本ごとの自由とする．本仕様は判別の条件だけを固定する．
- 回路図の配線の接続の検査．
  様式ではなく接続の正しさを見るものであり，
  `scripts/check-diagram-connectivity.mjs` が別に担う．
  ただし「読み取れない入力」の共通の部品は同検査も使う．
  同じ穴を持つことを実測で確かめたためである．
- 紙入稿データからの透明効果の除去．`docs/spec/print-layout.md` が扱う．
- 図の内容そのものの品質（比喩・用語・検算）．
  `tomio2480/settings` の `techbook-authoring` Skill が扱う．
- 登録した別スタックが図の大多数へ当たる状態の検出．
  [Issue #222](https://github.com/tomio2480/techbook-template/issues/222) が扱う．
