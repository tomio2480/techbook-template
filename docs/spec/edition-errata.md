# 版管理と正誤表運用

書籍の版（初版・第 2 版ほか）は semver と GitHub Releases で管理する．
正誤情報は `errata/errata.yml` へ一元記録する．その運用ルールを定める．
正誤情報は公開正誤表サイト（`tomio2480/errata`）から定期収集される．

## 用語

表 1. 版管理・正誤表運用で使う用語．

| 用語 | 意味 |
|---|---|
| 版（edition） | 書籍の版．semver の major と一致させる（初版 = v1.x.x） |
| 原本 | `errata/errata.yml`．正誤情報と版一覧の一次データ |
| slug | 公開サイトの URL に使う識別子．リポジトリ名から推測できない名前にする |
| applies_to | 正誤が該当する版の一覧 |
| fixed_in | 修正を本文へ反映した版．未反映なら記入しない |

## 版番号のルール

- `package.json` の version（semver）の major を版番号とする．
  `v1.x.x` が初版，`v2.x.x` が第 2 版である．
- minor / patch は出版前の改訂・軽微修正に使う．出版とは対応させない．
- 未出版（`editions` が空）の間，major は 1 のままにする．
- `config/book.yaml` の version の major も `package.json` と一致させる．

## 出版時のフロー

出版（入稿・頒布）のたびに次の手順を踏む．

1. 第 2 版以降の場合，`npm version major` で版番号を繰り上げる．
   初版の場合は 1.x.x のまま進める．
2. `errata/errata.yml` の `editions` へ新しい版を追記する．
   `release` には手順 4 で作られるタグ名（`v` ＋ そのときの version）を書く．
3. この版で本文へ反映した正誤があれば，該当項目に `fixed_in` を記入する．
4. main へ push（マージ）すると release ジョブが version のタグで
   Release を作成する．PDF は版のアーカイブとして保管される．

`editions` は公開正誤表サイトの収集用データである．
奥付の発行履歴（`99-colophon.md` への手書き）を，ここから自動生成
することはしない．理由と方針は `docs/spec/colophon.md` の
スコープ外節を参照する．

## 正誤表の運用

- 正誤が見つかったら，確認のうえ `errata` へ 1 項目ずつ追記する．
  読者からの報告・著者自身の発見のどちらも同じ形式で記録する．
- 記入時点では `applies_to` のみ書き，`fixed_in` は書かない．
- 本文を修正した PR では，原稿の修正と `fixed_in` の記入を同時に行わない．
  `fixed_in` は出版時（版が確定した時点）にまとめて記入する．
- スキーマの詳細は `errata/errata.yml` 冒頭のコメントと記入例を参照する．

## まえがきへの正誤表案内

正誤表の存在を読者へ確実に届けるため，まえがき（`00-preface.md`）へ
正誤表案内を必ず含める．奥付（`99-colophon.md`）の案内と独立に運用する．

- まえがきの原稿に，単独の段落として `{{errata}}` マーカーを書く．
  `scripts/inject-colophon.mjs` が奥付と同じ案内文へ置き換える．
- `config/book.yaml` の `errata.url` が未設定の場合，案内は出力されない．
  マーカーが除去されるだけで，ビルドは失敗しない．
- マーカーの欠落は `npm run check:preface`（`scripts/check-preface-errata.mjs`）
  が警告する．`npm run build` の先頭でも自動実行される．
  欠落は警告であり，ビルド失敗はしない．
- コードブロックや HTML コメントの中に書いたマーカーは欠落として扱う．
  段落にならず案内へ置き換わらないためである．
  存在すると見なせば，案内が落ちたまま検査を通してしまう（Issue #81・PR #85）．

## 検証

`scripts/check-errata.mjs` が次を検査する．
`npm run check:errata` で単独実行でき，`npm run build` の先頭でも自動実行される．
スキーマの単体テストは `npm test` に含まれる．

- book 節：slug の形式・title の存在（`book.yaml` との不一致は警告）．
- editions 節：版番号の 1 起点連番・日付形式・release タグと版番号の整合．
- 版整合：最新版番号 = `package.json` の major（未出版なら major = 1）．
- errata 節：必須キー・`applies_to`／`fixed_in` の参照整合．

## 公開サイトとの連携

- 公開正誤表サイト（`tomio2480/errata`）が原本を定期収集し，
  一覧・版別の正誤表ページを生成する．
  本テンプレートを第三者が利用する場合，サイト名は自身の環境へ読み替える．
- `editions` が空の間，公開サイトには掲載されない．
  初版出版時に `editions` を記入すると次回収集から自動掲載される．
- 読者からの正誤報告は公開サイト側の Issue で受け付けられ，
  確認後に本リポジトリへ Issue として転記されてくる．
  転記された Issue は通常の正誤フロー（`errata` へ追記）で扱う．
