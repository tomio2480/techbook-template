# 紙入稿要件 要求・要件（雛形）

印刷所へ入稿するための要件を書き留める雛形である．
要件は印刷所ごとに違うため，本テンプレートは数値を持たない．
枠組みと，現状との差分を測る観点だけを持つ．数値は書籍のリポジトリで埋める．

## この雛形の使い方

入稿先を決めた時点で書き始める．入稿の直前に集め直すと，
満たしていない項目の発見が遅れ，素材の作り直しが間に合わない．

書籍のリポジトリでは次の手順で埋める．

1. 見出しの「（雛形）」を外し，入稿先の名前を添える．
2. 本節を消す．手順の説明は，埋め終えた文書には要らない．
3. 印刷所の公開資料から表 2 を埋める．数値は原文のまま写す．
4. 出力した PDF を測り，表 3 の判定を入れる．測り方は表 4 に示す．
5. 資料から読み取れない項目を「印刷所へ確認する事項」へ残す．

**本テンプレートでは埋めない．** 入稿先は書籍ごとに変わるためである．
実在する印刷所の数値を雛形へ書くと，別の印刷所を使う利用者を誤らせる．
表 2 の要件の欄に置いた括弧書きは，記入の目安を示す例であり，
特定の印刷所の要件ではない．

## 背景と要求（why）

入稿の要件は印刷所ごとに違う．解像度・塗り足し・ページ数の単位・
表紙の扱い・ファイル名の規則が，いずれも印刷所の資料に散っている．
入稿先を決めるたびに，要件を集める作業が発生する．

要求は次のとおりである．

- 散っている要件を 1 か所へ写す．入稿の直前に集め直す作業をなくす．
- 満たしていない項目を実測で明らかにする．
  推測で「たぶん大丈夫」と扱わない．
- 測り方を残し，別の書籍でも同じ手順を使えるようにする．
- 印刷所の名前と数値をテンプレートへ固定しない．
  入稿先は書籍ごとに変わり，要件も改訂されるためである．

価値提案は次のとおりである．入稿先を決めた執筆者は，
測る観点と表の枠を引き継ぎ，数値を埋める作業だけを引き受けられる．

| 塗り足し | 仕上がり線の外へ広げる絵柄．裁ちのずれを吸収する |
| 表紙 4 ページ | 表紙・その裏・裏表紙の裏・裏表紙の 4 面．印刷所は表 1 から表 4 と呼ぶ |

| 実効解像度 | 紙面での描画寸法に対する画素の密度 |

## 印刷所の要件（what）

印刷所の公開資料から写す．数値は言い換えず原文のまま書く．
出典の欄には，末尾の一覧の番号を入れる．

表 2. 印刷所の要件と出典

| 項目 | 要件 | 出典 |
|---|---|---|

| 解像度（グレースケール） | （例: 350 dpi．網点を使うときは 600 dpi） | |
| 解像度（モノクロ 2 値） | （例: 600 dpi または 1200 dpi） | |

| トンボ | （例: 不要．寸法が正確なら中心を基準に面付け） | |
| 仕上がり寸法 | （例: B5 判は 182 x 257 mm） | |
| データ形式 | （例: PDF 可．JPEG は非推奨） | |

| 綴じ方向 | （例: 横書きは左綴じ） | |

| 白紙ページの扱い | （例: データは要らない．申込書へ明記する） | |
| ファイル名の規則 | （例: 半角英数字．ページ順の数字を入れる） | |
| 送信容量 | （例: 1 ファイルあたりの上限） | |

資料どうしで記述が食い違う場合もある．
どちらを採るかは，理由を添えて本節へ書く．片方を黙って消さない．

受け入れ条件は次のとおり．

- 表 2 の全行に要件と出典が入っている．
- 表 3 の全行に判定が入り，満たさない行に対応の予定または見送りの理由がある．
- 「印刷所へ確認する事項」が空であるか，未解決の理由が書いてある．

## 入稿仕様（決定）

要件と料金を照らして決めた内容を残す．
以降の実装と素材づくりは，本節を前提とする．

書く対象は，製本の方法・用紙・刷り色・部数・表紙の加工である．
決めた日付と，決めた人を添える．
料金は仕様を決める材料として記録するにとどめる．

## 現状との差分

出力した PDF を測り，要件に対する現状を並べる．
測った日付と，測った対象のファイルを添える．
表紙を本文と別データにする場合，測る対象が版で変わる点に注意する．
本文 PDF から表紙を外す指定は `docs/spec/print-layout.md` が扱う．
表紙単体の書き出しは `docs/spec/cover.md` が扱う．

### 差分を測る観点

表 4. 差分を測る観点と，見落としやすい点

| 観点 | 測り方 | 見落としやすい点 |
|---|---|---|
| ページ寸法・塗り足し | MediaBox と TrimBox の座標を辺ごとに比べる | 寸法の差は塗り足しの 2 倍になる．1 辺あたりは差の半分 |
| フォントの埋め込み | 全フォントの埋め込み状態を見る | 和文は Type 3 の輪郭で入る．一般的な形式ではない |
| 画像の色空間 | 各画像の `/ColorSpace` を見る | ICCBased 以外はプロファイルを持たない．DeviceRGB を見落とす |
| 画像の実効解像度 | 画素数を紙面での描画寸法で割る | 埋め込み画像だけでは，階調から焼かれた点画像を取り逃す |
| 透明効果 | `/None` でない SMask と，1 未満の `ca`・`CA` だけを数える | 指定の有無で数えると，不透明なものまで数える |
| ページ数 | 総ページ数を綴じの単位で割る | 表紙を数に含めるかは印刷所で決まる |
| ノンブル | ページ下端の帯から数字を拾う | 扉と奥付は元から持たない |
| 刷り色 | 各画像と描画の色空間を見る | カラーで組んだままでも誌面の見た目は変わらない |

観点のいくつかは，本テンプレートの組版の仕組みから生じる．
次の 3 つは，既定の設定で出した紙入稿用 PDF を測って確かめた（2026-08-24）．

- 塗り足しを付けた PDF は，MediaBox が仕上がりより大きい．
  仕上がりの位置は TrimBox に入る．寸法の差は天地または左右の合計であり，
  1 辺あたりの塗り足しはその半分にあたる．
  実測では MediaBox 188 x 263 mm，TrimBox 182 x 257 mm であり，
  1 辺は 3 mm であった．
  詳細は [紙入稿用 PDF 要求・要件](print-layout.md) を参照．
- 和文の書体は Type 3 として入る．中身は輪郭であり点画像ではない．
  文字の抽出もできる．先方の環境で書体が置き換わる事態は起きない．
  ただし一般的な形式ではないため，出力機での扱いは確かめたい．
- 絵柄には装置依存の色空間を持つ点画像が混じる．
  Chromium が CSS と SVG の階調を焼き込むためである．
  文字と線はベクターのまま重なるため，輪郭は鈍らない．

透明効果の数え方は派生リポジトリの実測による．
`techbook-introduction-to-electronics-basic-led` では 2 通りの数え方を比べた．
SMask や不透明度の指定をそのまま数えた件数は，透明を持つ図形の状態の数から
大きく外れた．`/SMask /None` や `ca 1` が混ざるためである．
表 4 の測り方は，この 2 つを除いた数え方を指す．

測定そのものにも落とし穴がある．いずれも 2026-08-24 の測定で踏んだ．

- PDF には，ページツリーから参照されないオブジェクトが残ることもある．
  間接オブジェクトを総なめにすると，そこまで数えてしまう．
  紙入稿用 PDF では `/Type /Page` が 54 個見つかった．
  一方でページツリーの `/Count` は 36 であった．
  数える対象は，ページツリーか資源から辿る．
- フォントの埋め込みは Type0 の記述だけでは分からない．
  埋め込みの情報は子孫フォントの記述子にある．
- 同じ書体について「埋め込みあり」と「なし」の両方が出たら，
  参照されないオブジェクトを数えている疑いを持つ．
  `/FontName` と `/FontFile` の対応を数え直して突き合わせる．
  この形で「コード用の書体が埋め込まれていない」と一度読み違えた．

測り方の詳細な手順と，そのとき使った道具は `docs/notes/` へ残す．
本文書は測った結果と判定を持ち，手順そのものは持たない．

## 印刷所へ確認する事項

公開資料から読み取れなかった事項を並べる．
解消したものは表 2 へ取り込み，本節からは消す．
消したことは変更記録へ 1 行残す．

## スコープ外

- 印刷の発注と納期の管理．
- 入稿先を変えた場合の要件．本文書は 1 つの入稿先を対象とする．
- 表紙の絵柄そのものの制作．
- 測定を自動化する仕組み．入稿は書籍の一生に数回であり，
  手で測る費用のほうが小さい．

## 変更記録

- YYYY-MM-DD: 種別（要求変更／要件変更／用語変更）・理由・関連 Issue または PR．
