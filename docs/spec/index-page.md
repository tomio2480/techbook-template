# 索引 要求・要件

用語から本文のページを引く索引の要求・要件を定める．
索引へ載せる語は執筆者が選び，ページ番号は組版の結果から解決する．
本文へ置いたアンカーから索引の骨組みを作り，参照の食い違いは機械で止める．

## 背景と要求（why）

技術書の読者は，通読するだけでなく用語から目的の記述を探す．
索引の有無が使い勝手を分ける．
本テンプレートには索引の仕組みが無い．
原稿・テーマ CSS・仕様のいずれにも記述が無く，各書籍が組み方から作ることになる．

索引は派生リポジトリで先に作り，用語 76 件を載せて運用している．
対象は `techbook-introduction-to-electronics-basic-led` である．
上流へ引き取れば，以後の書籍が同じ作業を繰り返さずに済む．

要求は次のとおりである．

- ページ番号を原稿へ書かずに済ませる．
  手で書くと，本文が 1 行増えるたびに索引が古くなる．
- 索引へ載せる語の選定を執筆者の判断に残す．
  本文から機械で語を選ぶと，重要でない語まで並ぶ．
- 参照先の収集は機械へ任せる．
  本文のアンカーは機械で読める形であり，人が数え上げる必要は無い．
- 参照の食い違いを入稿前に止める．
  参照先が本文に無くても，ビルドは成功してしまう．
  Vivliostyle は解決できない `target-counter` を `??` で埋め，警告も出さない．
  気付かないまま `??` を刷った PDF を入稿しかねない．
  黙って通る失敗であり，機械で止める必要がある．
- 索引を持たない書籍でも壊れない状態を保つ．
  本テンプレートは書籍の性質を選ばない．

価値提案は次のとおりである．執筆者は載せる語を選ぶ作業だけを引き受け，
参照先の収集・区分の割り振り・ページ番号の解決を仕組みへ預けられる．

## 用語集（ユビキタス言語）

表 1. 索引で使う用語の定義

| 用語 | 意味 |
|---|---|
| 索引 | 見出し語からページを引く一覧．巻末へ置く |
| 見出し語 | 索引へ並べる語．索引では `.index-term` として組む |
| 読み | 見出し語を五十音で並べるための仮名．本文のアンカーへ書く |
| 区分 | 索引を分けるまとまり．英字・数字・あ行〜わ行・未分類 |
| アンカー | 本文中の参照先．`id` を持ち，文字を出さない空の `a` 要素 |
| 参照 | 索引から本文のアンカーへ向かうリンク 1 件．`.index-page` として組む |
| 骨組み | 本文のアンカーから作る索引の下書き．執筆者が取捨して原稿へ移す |

## 要件（what）

### 索引の原稿

- 索引の原稿を `src/chapters/99-index.md` へ置く．
  `vivliostyle.config.js` の `entry` では，あとがきと奥付の間へ並べる．
- frontmatter で `class: index` を与える．
  既存の原稿（`class: afterword` など）と同じく接頭辞は付けない．
- 骨組みの生成と参照の検査は，この `class` で索引の原稿を見分ける．
  ファイル名には依存しない．原稿を改名しても仕組みは壊れない．
- ただし目次の章番号の除外だけはファイル名で判定する．
  原稿名には `index` を含める（`docs/spec/toc-numbering.md` 参照）．
  索引に章番号が付くと，本文の章と同じ扱いに見えてしまう．
- **ページ番号を原稿へ書かない．** 参照は `href` だけを持つ．
- 索引を持たない書籍は，原稿を消して `entry` から外せば足りる．
  索引が無い状態でも，骨組みの生成・参照の検査・ビルドが通る．
- 目次（`src/chapters/toc.html`）に残る索引の項目は，次のビルドが取り除く．
  手で消す必要は無い．目次は手で書き足した項目を残す作りであり，
  外した原稿への項目もそのまま残ると `??` を刷ってしまう．

### 本文のアンカー

- 索引に載せる語の直前へアンカーを置く．書式は次のとおりとする．

  ```html
  <a id="idx-forward-voltage-1" data-index="順方向電圧" data-yomi="じゅんほうこうでんあつ"></a>
  ```

- `id` は `idx-` で始め，書籍の中で一意とする．
  末尾の連番は，同じ見出し語の何件目かを示す．
- `data-index` は骨組みへ出す見出し語である．
  省略したときは `id` から作った仮の見出し語を出し，執筆者へ書き換えを促す．
- `data-yomi` は区分と並び順を決める仮名である．
  見出し語が英字または数字で始まるときは要らない．
  和文の語で省略したときは「未分類」の区分へ集める．
- アンカーは本文へ文字を出さない．前後の字送りへも影響を与えない．

### ページ番号の解決

- 参照のページ番号は `target-counter(attr(href url), page)` で解決する．
  目次のページ番号と同じ仕組みであり，本文が動いても古くならない．
- 同じ見出し語に参照が 2 件以上あるとき，2 件目以降の前へ区切りを出す．
- 索引の体裁はテーマ CSS の変数（`--index-*`）で調整する．
  対象は段数・段間・区分見出しの体裁・参照の区切り文字である．

### 骨組みの生成

- `npm run gen:index` で本文のアンカーを走査し，骨組みを標準出力へ出す．
- 原稿を書き換えない．出力を見て取捨し，執筆者が索引の原稿へ移す．
  載せる語の選定を執筆者の判断に残すためである．
- 見出し語が同じアンカーは 1 件へまとめ，本文での出現順に参照を並べる．
- 区分は読みの頭で決める．既定の区分は英字・数字・あ行・か行・さ行・た行・
  な行・は行・ま行・や行・ら行・わ行・未分類とする．
- 区分の中では，和文の語を読みの五十音順に，英字と数字を符号順に並べる．
- 見出し語または読みが欠けているものには目印を付け，件数とともに知らせる．

### 参照の検査

- `npm run check:index` で索引と本文の食い違いを調べる．
  見つかればビルドを止める．`npm run build` の前段へ置く．
- 調べることは次の 4 つである．
  - 参照の `href` が指す原稿ファイルは実在するか．
  - 参照の `href` が指すアンカーは，その原稿ファイルに実在するか．
  - 本文のアンカーのうち，索引から参照されていないものが無いか．
  - アンカーの `id` が書籍の中で重複していないか．
- 索引の原稿が無い書籍では，何も調べずに成功で終える．

### 紙入稿との関係

- 索引は章扉を持たない区分である．小口のつめを付けるときは
  `config/book.yaml` の `print.section_tabs` へ 1 行足す．
  つめの仕組みは `docs/spec/print-layout.md` が扱う．
- 索引のページ数は本文の量で決まる．面付けの調整ページは従来どおり
  `print.filler_before` の指す区分の直前へ入る．

受け入れ条件は次のとおり．

- `npm run gen:index` が本文のアンカーから骨組みを出し，原稿を書き換えない．
- 骨組みが区分ごとに分かれ，区分の中が読みの順で並ぶ．
- `data-yomi` を持たない和文の語が「未分類」の区分へ目印付きで出る．
- `npm run check:index` が参照の食い違いを見つけ，ビルドを止める．
- 索引の原稿を消して `entry` から外しても，生成・検査・ビルドが通る．
  目次から索引の項目が消え，`??` を刷らない．
- `npm run build` が索引のページを出し，参照へ本文のページ番号が入る．
- 本文を増減させると，索引のページ番号が組版の結果へ追従する．
- 本文へ置いたアンカーが，誌面の見た目を変えない．
- `npm test` と `npm run build:print` が従来どおり通る．

## スコープ外

- 本文からの見出し語の自動抽出．載せる語は執筆者が選ぶ．
- 読みの自動推定．漢字の読みは文脈で決まり，機械では誤る．
- 見出し語の下位項目（サブエントリ）．派生リポジトリの 76 件では要らなかった．
- 「〜を見よ」「〜も見よ」の相互参照．
- 連続するページ番号を範囲（`12-15` の形）へまとめる表示．
- 索引の原稿の自動更新．骨組みの出力までを担い，原稿は執筆者が持つ．
