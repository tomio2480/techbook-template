# 表紙・裏表紙テンプレート 要求・要件

表紙（表 1）と裏表紙（表 4）を，背景画像と文字情報の統合で組む
テンプレートの要求・要件を定める．文字は画像化せず実テキストで重ねる．
本文と別に渡す入稿データの書き出しも扱う．

## 背景と要求（why）

- 現状の表紙は文字のみの簡素なページであり，裏表紙はバーコード配置の
  受け皿となる最小構成にとどまる（`docs/spec/isdn.md` のスコープ外扱い）．
- 入稿品質の表紙・裏表紙をテンプレートから作れる状態にする．
  執筆者は背景画像の差し替えと文字の書き換えだけで独自の表紙を得る．
- タイトル・著者名などの文字情報は画像化せず，テキストとして重ねる．
  テキストリーダー等の支援技術が文字情報を読める状態を保つためである．
- 審美的な文字配置の調整はテーマ CSS に集約する．
  原稿（Markdown）と体裁（CSS）の分離という既存方針を表紙にも適用する．

## 用語集（ユビキタス言語）

表 1. 表紙・裏表紙テンプレートで使う用語

| 用語 | 意味 |
|---|---|
| 表紙（cover） | 本の最初のページ（表 1）．`src/chapters/cover.md` で書く |
| 本扉（title-page） | 表紙をめくった 1 枚目．`src/chapters/title-page.md` で書く |
| 裏表紙（back-cover） | 本文 PDF の最終ページ（表 4）．`src/chapters/back-cover.md` で書く |
| 背景画像 | ページ全面に敷く装飾画像．表紙は `img` 要素，裏表紙は CSS 背景で敷く |
| プレースホルダー画像 | テンプレート初期状態の背景画像．執筆者が差し替える前提で置く |
| 文字情報 | タイトル・著者名など，実テキストのまま背景の上へ重ねる情報 |
| 規定位置 | ISDN バーコードの配置位置（裏表紙右上）．`docs/spec/isdn.md` を参照 |
| 表紙単体の入稿データ | 本文と別に渡す表 1・表 4 の PDF．`npm run build:cover` で書き出す |

## 要件（what）

- 表紙ページを余白 0 の専用ページ（`@page cover`）で組む．
  - 背景画像をページ全面に敷く．既定はプレースホルダー画像とする．
  - 表紙の背景は `cover.md` の `img` 要素として敷き，文字の下へ回す．
    CSS 背景では敷かない．ページを仕上がりより大きく組むと，
    Chromium が背景の SVG を 72 dpi のビットマップへ平坦化する．
    紙入稿用ビルドの塗り足しが該当する（`docs/spec/print-layout.md`）．
    読み上げでは装飾として扱うため `alt` は空にする．
  - タイトル・著者名は `cover.md` の実テキストをそのまま重ねる．
  - 柱・ノンブルは出力しない．
- 表紙の直後に本扉ページ（`title-page.md`）を置く．
  - 背景は敷かず，タイトル・著者名のみを簡素に組む（従来の表紙の体裁）．
  - 柱・ノンブルは出力しない．
- 裏表紙は既存の余白 0 ページ（`@page back-cover`）を維持して拡張する．
  - 背景画像をページ全面に敷く．既定はプレースホルダー画像とする．
  - 文字情報の領域は，バーコード規定位置（右上）を避けた既定余白を持つ．
  - バーコードの白地と読み取り性を損なわない（`docs/spec/isdn.md` の要件）．
  - バーコード脇の文字情報（番号・コード行・発行者）の内容は
    `docs/spec/isdn.md` の要件に従う．
- 表紙・裏表紙を本文と別の PDF として書き出せるようにする．
  - `npm run build:cover` で `dist/cover.pdf` と `dist/back-cover.pdf` を出力する．
  - 多くの印刷所は表紙を本文と別のデータで受け取るためである．
  - 表 1 と表 4 を 1 枚続きにせず，別のファイルへ書き出す．
    別にすると印刷所が背幅を両者から半分ずつ取るためである．
    背幅を自分で加える必要が無くなる．
  - 寸法は紙入稿用の本文へそろえ，塗り足しを含める．
    塗り足しの量は `docs/spec/print-layout.md` が単一の出所である．
    表紙のためだけに同じ値を書き写さない．
  - 仕上がり線を PDF の TrimBox へ記録する．
  - 裏表紙はバーコードを載せる．書き出す前に ISDN の設定を検査する．
  - 電子書籍用の `npm run build` は挙動を変えない．
- 表紙・本扉の書名・著者名は `config/book.yaml` の `title`・`author` を
  単一の出所とする．マーカー（`{{book-title}}`・`{{book-author}}`）で
  誌面へ流し込む．
  - 文字列データは共有し，体裁（位置・大きさ・色）は表紙と本扉で
    独立に調整できる状態を保つ．表紙のデザイン変更が本扉へ波及しない．
  - コード文脈（`code`・`pre`・`script`・`style` 等）内のマーカーは
    置換しない．作例にマーカー文字列そのものを載せられるようにする．
- 文字配置・書式（位置・サイズ・色・揃え）と背景画像は，
  テーマ CSS の変数（`--cover-*`・`--back-cover-*`）で調整できるようにする．
  - 配色の変数は既存の 2 層トークン構成に従い `palette.css` に置く．
- プレースホルダー背景画像は `src/assets/images/` へ置く（表 1 用・表 4 用）．
  - 既定の文字色との可読性を保つ淡色基調とする．
  - 配色は基調色パレットへ揃え，デザイン言語（工業系の教科書風）に沿わせる．

受け入れ条件は次のとおり．

- `npm run build` で，表紙に背景画像とタイトル・著者名が重なって出力される．
- 表紙の次ページに本扉が出力され，従来どおりの簡素な体裁を保つ．
- 裏表紙に背景画像が敷かれ，ISDN バーコードが規定位置で読み取れる．
- 表紙・裏表紙の文字が PDF 上でテキストとして抽出できる（画像化されない）．
- テーマ CSS の変数上書きだけで文字の位置・サイズ・色を変更できる．
- `config/book.yaml` の `title`・`author` の変更が表紙・本扉の両方へ反映される．
- `npm run build:cover` が `dist/cover.pdf` と `dist/back-cover.pdf` を
  1 ページずつ出力する．
- どちらも塗り足しを含む寸法で組まれ，TrimBox に仕上がり線が入る．
- 書き出した PDF でも文字がテキストとして抽出できる．
- 書き出し後の作業ツリーに一時ファイルが残らない．
- `npm test` と `npm run build` 内の機械検査が全件通る．

## スコープ外

- 背景画像の自動生成．執筆者が用意した画像の利用を前提とする．
- 背表紙（スパイン）・表 2・表 3．本仕様は表 1・表 4 だけを対象とする．
  本文 PDF へ同梱するかは `docs/spec/print-layout.md` が扱う．
- トンボの付与．不要とする印刷所が多く，要件も分かれるためである．
  塗り足し（bleed）は `docs/spec/print-layout.md` が扱う．
  表紙の絵柄も塗り足しの端まで広げる．
