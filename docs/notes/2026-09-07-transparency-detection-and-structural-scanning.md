# 透明の検出で踏んだ全文走査の穴と，変異が見つけたテストの穴

図版 SVG の透明の指定を検出する検査を足した（Issue #211）．
全文へ正規表現を当てる作りが，`title` や `desc` の説明文を指定と取り違えた．
読む場所を文書の構造で分け，既存の色の検査にあった同じ誤検出もまとめて直した．
変異 18 種のうち 2 種が生き残り，テスト側の穴を 2 つ見つけた記録である．

## 背景

図版 SVG の配色検査は `scripts/check-diagram-luminance.mjs` にある．
読むのは `fill`・`stroke`・`stop-color` の値だけである．
半透明で塗ると，合成後の見かけの明度が登録した明度段から外れても検査を通る．
この盲点を塞ぐため，透明の指定を違反として報告する検査を足した
（[Issue #211](https://github.com/tomio2480/techbook-template/issues/211)）．

要求要件は同時に `docs/spec/diagram-style.md` へ固定した．

## 判断

### 全文への正規表現をやめ，文書の構造に沿って読む

はじめは SVG の全文へ正規表現を当てた．
`opacity="0.5"` と `style="opacity:0.5"` を 1 本の走査で拾える．

これは適合する図を落とす．次の 3 つが違反になった．

```
<title>Set opacity: 0.5</title>
<desc>fill: red</desc>
<path aria-label="opacity: 0.5"/>
```

本テンプレートは図へ `title`・`desc` を付ける方針である．
説明文へ宣言と同じ並びが現れることは避けようがない．
図の作りかたを制約するより，検査を直すほうが筋にかなう．

読む場所を分けた．属性はタグの中だけ，CSS の宣言は `<style>` 要素の中身と
`style` 属性の値だけを読む．

**同じ誤検出は既存の色の宣言の検査（`CSS_COLOR_PROPERTY`）にもあった．**
本作業で持ち込んだものではなく，元からあった．同じ経路へ載せてまとめて直した．

タグの切り出しでは引用符を見る．`<[^>]*>` だと
`aria-label="a > b"` で切れ，同じタグの後続の属性を読み落とす．
誤検出を直す変更が，逆方向の見逃しを作りうる．

### CSS コメントは取り除かず空白へ置き換える

無効化した旧指定をコメントで残しただけの図が落ちていた．
コメントは描画へ影響せず，検査が見る宣言にも当たらない．

ただし取り除くと別の誤検出を生む．

```
<style>.x { opac/**/ity: .5 }</style>
```

CSS コメントはトークンの境界として働く．
ブラウザーはこれを `opacity` とは読まない．
コメントを空文字へ置き換えると `opacity: .5` へ連結し，
効かない指定を違反として報告する．空白 1 字へ置き換えれば境界が残る．

### `opacity` の名を持たない透明も対象にする

`mask`・`filter`・`mix-blend-mode` は `opacity` の名を含まない．
灰色のマスクはアルファを作り，`filter` は `feFuncA` や `flood-opacity` で
同じことができる．PDF ではソフトマスクになる．

静的には「本当に透明になるか」を決められない．
白一色のマスクは不透明であり，`feColorMatrix` は透明を生まないこともある．
そのため当初は判断を保留し，レビューへ切り分けを委ねた．

決め手は「無彩色だけで組めば既存の色検査にも掛からない」ことであった．
検査を通り抜けたまま刷り上がりの変わる経路が残る．
そのときは見逃しの害のほうが大きい．
値による場合分けをしない既存の方針とも揃う．

### 色の収集は全文のまま残した

同じ構造の直しを `parseColorValues` へも当てようとしたが，既存テストが落ちた．

```
<svg><!-- a <!-- b --> fill="#cc0000" --></svg>
```

XML コメントの除去後，`fill="#cc0000"` はタグの外に残る．
タグへ限ると拾わなくなる．このテストは fail-closed の保証として置いた．
由来は CodeQL の `js/incomplete-multi-character-sanitization` である．

落ちること自体は正しい可能性がある．ブラウザーもこれを色として扱わない．
それでも，**テストを通す目的で既存の保証を書き換えるのは避けた．**
別 Issue（[#225](https://github.com/tomio2480/techbook-template/issues/225)）へ切り出した．

## 変異が見つけたテストの穴

変異を 18 種当て，狙ったテストだけが落ちることを確かめた．
最初の実行では 2 種が生き残り，どちらもテスト側の穴であった．

表 1. 生き残った変異と，足りなかった対照

| 生き残った変異 | 足りなかったもの |
|---|---|
| タグへの限定を外して全文を読む | 属性形がテキストノードに現れる例 |
| タグの抽出で引用符を見ない | 属性値に `>` を含むタグの例 |

1 つめは，最初に足した例が判別できていなかった．
`<title>opacity="0.5" と書く</title>` と書いたが，
`opacity` の直前が `>` であり，正規表現の `\s` 境界に当たらない．
全文を読んでも一致せず，変異を殺せなかった．
`<title>例として opacity="0.5" と書く</title>` へ直して判別できるようになった．

**陰性対照は「違反にならない」だけでなく「その理由が意図した経路である」ことまで
確かめないと，変異を殺せない．**

もう 1 つ，変異そのものが空振りした例もあった．
`const withoutComments = stripXmlComments(svgText);` を狙った．
ところが同じ行が `parseColorValues` にもある．
先頭一致の置換は，そちらを壊していた．
落ちたテストは別物で，狙った検査は素通りしていた．
後続の行まで含めて特定し直した．

Windows の作業ツリーは CRLF で checkout される．
改行を含む変異の文字列を LF のまま当てると一致しない．
空振りは「落ちない変異」と見分けが付かないため，
変異が当たらない場合は失敗として扱うようにした．

## 代替案と棄却理由

- **XML パーサを入れる案**：不採用．依存が 1 つ増える．
  検査が必要とするのはタグの範囲と宣言の範囲だけであり，釣り合わない．
  ただし整形式でない SVG の扱い（[Issue #221](https://github.com/tomio2480/techbook-template/issues/221)）で
  再検討の余地がある．
- **`mask`・`filter` をスコープ外として spec へ明記する案**：不採用．
  現行の図版に使用は無く，入稿データ側では
  `scripts/check-print-transparency.mjs` が `/SMask` を数える．
  二重の網はあるが，図版の段階で通ることが規約の空文化につながる．
- **CSS コメントの中の字句を禁じる案**：不採用．
  無効化した旧指定をコメントで残すのは正当な書き方である．
  規約が実務と食い違う．
