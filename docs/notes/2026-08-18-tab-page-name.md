# つめの流し込み要素が章扉のページ名を奪っていた件

小口のつめが章扉にも刷られていた不具合（Issue #133・PR #135）の記録である．
原因は Issue の見立てと違い，つめの流し込み要素の置き場所にあった．
切り分けの手順と，レビュー 3 巡で塞いだ HTML 走査の穴も残す．

## 目次

- 背景
- 判断
- 代替案と棄却理由

## 背景

`docs/spec/print-layout.md` はつめを章扉へ出さないと定めている．
実際には扉にも出ていた．素のテンプレートでも扉 4 枚すべてで再現した．

Issue の見立ては「`@page chapter-opening` が `@right-top` に触れていないため」だった．
そこへ `content: none` を足す案が示されていた．
当ててビルドし直したが，つめは消えなかった．

実測で分かったのは，Issue に書かれていない食い違いである．
紙入稿用の扉にはノンブルが出ていた．電子書籍用（`dist/book.pdf`）の扉には出ない．
`@page chapter-opening` は柱とノンブルの両方を打ち消す．
扉にノンブルが出るなら，扉のページは `chapter-opening` として組まれていない．
つまり `@right-top` を足しても当たる先が無い．

## 判断

原因は，つめの流し込み要素 `<aside class="print-tab-mark">` を
`body` の先頭へ入れていたことである．
扉より前にこの要素があると，扉のページは `body` から始まった扱いになる．
扉が名乗る `page: chapter-opening` は効かなくなる．
結果として `@page tab:right` の `@right-top` が扉へ当たり，つめが出ていた．

置き場所を扉の中の末尾（閉じタグの直前）へ変えた．
扉のページは `.chapter-opening` から始まるためページ名が保たれ，
つめは扉へ出ず，柱とノンブルの打ち消しも効いたままになる．

`print.css` は変更していない．`html[class*="print-tab-"] body { page: tab; }` は
原因ではなく，扉の中へ移せばページ名は保たれる．

## 代替案と棄却理由

表 1. 検討した置き場所と採否

| 置き場所 | 扉のつめ | 扉のノンブル | 採否 |
|---|---|---|---|
| `body` の先頭 | 出る | 出る | 不採用．元の実装 |
| 扉の直後 | 出ない | 出ない | 不採用．下記の理由 |
| 扉の中の末尾 | 出ない | 出ない | 採用 |

扉の直後は，一度は実装してコミットまで進めた．
レビューで指摘を受けて取り下げた．`theme.css` の次の指定が効かなくなるためである．

```css
.chapter-opening.no-repeat-heading + section.level1 > h1
```

この指定は扉と本文の隣接を前提にしている．
間に要素を挟むと隣接セレクタが外れ，`no-repeat-heading` を有効にした章で，
隠しているはずの章タイトル帯が紙入稿用だけ戻る．

CSS 側のセレクタを `~` へ緩める案も採らなかった．
紙入稿用の都合でテーマの体裁を書き換えると，電子書籍用との差が広がる．

`page: tab` をやめて `@page :right` へ載せ替える案も試した．
つめが出る条件は満たすが，扉のページ名の問題は解けず，
`print.css` の変更も要る．原因が別にあると分かった時点で戻した．

## 切り分けの手順

`npm run build:print` は 1 回およそ 4 分かかる．
仮説ごとに回すと時間が溶ける．最小構成を作って 1 変数ずつ動かした．
1 回およそ 20 秒で回り，同じ結論に届く．

- 素の HTML と CSS を用意し，`vivliostyle build` へ直接渡す．
- 変えるのは 1 箇所だけにする．今回は `<aside>` の位置である．
- 判定はページの描画内容から数値で取る．
  ノンブルの有無は，フッター帯（ページ高 − 45 pt より下）の文字で見る．
  つめの有無は，幅 8 mm・高さ 16 mm の塗り矩形で見る．

スタイルの渡し方で挙動が変わる点にも注意が要る．
`-s` で渡したスタイルは利用者スタイルになる．
`<link>` から読んだものは著者スタイルになる．
両者で `@page` の効き方が違った．
本番と同じ経路（テーマ CSS ＋ `--style`）で確かめるまで結論を出さない．

## レビューで塞いだ穴

扉を探す処理は HTML の文字列走査である．Codex から 3 巡にわたり穴を指摘された．
いずれも「取りこぼすと `body` の先頭へ黙って戻り，直したはずの事象が再発する」
という同じ危険につながる．前提はすべて実挙動で確かめてから受け取った．

表 2. 指摘と確かめた前提

| 指摘 | 確かめたこと | 対応 |
|---|---|---|
| `class` の引用符が `"` だけ | `hasChapterOpening` は引用符を問わず章と判定する | `"…"`・`'…'`・引用符なしを受け取る |
| 属性値の中の `>` でタグが切れる | VFM は属性値の `>` をエスケープせず出力する | タグの終わりを引用符の外側の `>` で決める |
| コメントや raw text の中を要素と読む | VFM はコメントをそのまま `body` の直後へ残す | `<!--` から `-->` と raw text を読み飛ばす |

コメントの件は本テンプレートに直接届く．各章は先頭へ `textlint-disable` の
コメントを置く決まりであり，コメントは常に扉より前にある．

自分の実装のバグも 1 つ見つかった．`\bchapter-opening\b` はハイフンを
語境界と見なすため，`chapter-opening-note` のような別クラスを扉と誤認していた．
指摘を受けて書いたテストで気づいたものである．

走査は 40 行程度に収め，HTML パーサの追加は見送った．
`<template>` や CDATA といった理屈上の穴は残るが，VFM の出力には現れない．
テンプレートへ依存関係を増やす代償に見合わないと判断した．
