## 決めたこと

spec を先に書き（#164），実装を 2 本へ分けた．索引（#156 → #157）と同じ進め方である．

表 1. PR の分け方と扱った範囲

| PR | 扱った範囲 |
|---|---|
| #164 | 要求・要件のみ．`print-layout.md`・`cover.md`・`isdn.md` |
| #166 | `print.cover.include`．本文 PDF から表紙を外す |
| #167 | `npm run build:cover`．表紙単体の入稿データ |

本テンプレートでの実測は，表紙の有無によらず全 36 ページであった．
表紙 2 ページを抜くと後続の面がずれ，MEMO ページが
5 箇所 5 ページから 6 箇所 7 ページへ増えて差を埋める．
派生リポジトリの実測（64 ページ）と同じ性質である．
ただし総ページ数が必ず一致するとは限らない．MEMO ページの入る位置と枚数は変わる．

## 還元元の定数は書き写さず出所から読む

派生リポジトリの `build-cover.mjs` は，紙面 188 x 263 mm と
仕上がり 182 x 257 mm を定数で持っていた．書籍 1 冊なら足りる．

テンプレートでは足りない．塗り足しの量は入稿先ごとに変わり，判型も本ごとに違う．
定数を持つと，`--bleed` を変えた本で検査だけが古い値のまま残る．
`docs/spec/cover.md` にも「塗り足しの量は `docs/spec/print-layout.md` が
単一の出所である．表紙のためだけに同じ値を書き写さない」と書いてあった．

そこで `print.css` の `--bleed` を読み，紙面と仕上がりの隔たりが
その値になっていることを検査する形にした．判型の寸法は検査へ持ち込まない．
表 1 と表 4 の仕上がり寸法が互いにそろっていることは別に確かめる．

**還元では，先方が定数で持っている値の出所を探す．**
書籍側では定数で済んでいた値が，テンプレート側では設定になる．

## 寸法の検査は差ではなく四辺で量る

最初の実装は，紙面と仕上がりの **寸法の差** が塗り足し 2 つ分かを見ていた．
仕上がりが紙面の中で寄っていても，差が合えば通る．
左と地が 0 mm・右と天が 6 mm の版が入稿へ届く形だった．

紙面から仕上がりまでの隔たりを四辺それぞれ量る形へ直した．
外れた辺だけを名前つきで示す．

**寸法の合計や差で量ると，位置の誤りが見えない．**
位置が意味を持つ検査では，辺・角・端のように場所を特定できる単位で量る．

## 出力の検査は誌面の中身まで見る

ページ数と矩形だけを見ていたため，中身が空でも成功していた．
`config/book.yaml` に `title` や `author` が無いと，流し込みは警告だけで進み
空文字へ置き換わる．白紙同然の表紙が入稿データとして出来上がる．

2 段で直した．設定の不足は組む前に弾き，書き出した後は PDF から
テキストを取り出して求める文字が入っていることを確かめる．

抽出した漢字は康熙部首へ化けることがある．「行」が U+2F8F になった．
素の包含判定では原稿の文字列と一致しない．
突き合わせの前に NFKC でそろえ，空白を落とす．

**PDF を機械で検査するときは，取り出した文字がそのままの字とは限らない．**

## 指摘の観察は正しくても解決案が spec と衝突することがある

3 巡目の指摘は「バーコードを欠いた裏表紙を弾け」であった．
観察は実挙動でも確かめられた．`inject-isdn.mjs` はバーコード画像が無いと，
番号が正しくても情報ブロックごと出力から消す．
`check-isdn.mjs` の「番号があるのに画像が無い」は警告どまりである．

しかし提案どおり「バーコードを一律で必須にする」と，
`docs/spec/isdn.md` の「番号未発行（空値）は正常として扱う」と衝突する．
ISDN を取らない本が表 4 の入稿データを作れなくなる．

裏表紙へ求める文字を `config/isdn.yaml` から引く条件つきの形にした．
発行済みなら番号を求め，未発行なら求めない．
情報ブロックは画像が無ければ丸ごと消えるため，番号のテキストの有無が
バーコードの有無の代理になる．

**指摘は観察と解決案に分けて受け取る．** 観察が正しくても解決案は採らないことがある．
採らない判断は理由とともに返信へ書く．黙って別の直し方をすると，
次の巡で同じ指摘が返ってくる．

## レビューの巡ごとに検査が 1 段ずつ深くなった

表 2. Codex の指摘と，足した検査

| 巡 | 指摘 | 足した検査 |
|---|---|---|
| 1 | 塗り足しを辺ごとに見よ | 四辺それぞれの隔たり |
| 2 | 文字を失った表紙を弾け | テキスト抽出と書名・著者名 |
| 3 | バーコードを欠いた裏表紙を弾け | 発行済み ISDN 番号 |

いずれも「出力が正しいか」を測る網の目を細かくする指摘であった．
最初の実装は「ページ数と寸法が合っていること」しか見ておらず，
入稿データとして成り立つかを見ていなかった．

**入稿のように後戻りが利かない出力では，形式より中身の検査が効く．**

lint summary は 3 巡目の直しで textlint を 1 件出した．
「確認を行わない」が冗長表現に当たる．CI のジョブはすべて pass の表示であった．
ジョブの色ではなく件数の表を読む．
