# VFM の段落境界と，前提を実挙動で確かめる規律

`check-preface-errata.mjs` が行をまたぐコードスパンを扱えるようにした際の記録である．
作業の途中で Issue の再現例とレビュー指摘の双方に，成り立たない前提が見つかった．
どちらも VFM で描画して初めて分かった．対象は Issue #112 と PR #121 である．

## 背景

`hasErrataMarker` は，まえがきに `{{errata}}` が単独の段落として書かれているかを
判定する．コードブロックや HTML コメントの中にあるマーカーは，段落にならず
案内へ置き換わらないため欠落として扱う．

Issue #112 は，行をまたぐコードスパンの中の `<!--` をコメント開始と誤認すると
報告していた．走査が 1 行の中で閉じるコードスパンしか扱わないためである．

## Issue の再現例が誤っていた

Issue が挙げた再現例は次のとおりである．

````markdown
`foo
<!-- bar`

{{errata}}
````

「2 行目の `<!--` はコードとして表示されるだけ」と説明されていた．
しかし VFM で描画すると `<p>` が 1 つ出るだけで，マーカーは現れない．
行頭の `<!--` は HTML ブロックの開始であり，段落を途中で切る．
直前の行に閉じ手の無いバッククォートがあっても，コードスパンは続かない．

つまりこの入力で出る警告は正しく，偽の警告ではなかった．
実際に直すべきだったのは，`<!--` が行頭に無い場合である．

````markdown
`foo
bar <!-- baz`

{{errata}}
````

こちらはコードスパンが 2 行目の末尾で閉じ，マーカーは単独の段落になる．
修正前のコードは偽の警告を出していた．

Issue の記述をそのまま受け取ってテストを書いた結果，誤った前提を
実行できる形で固定してしまった．レビューで検証するまで気づかなかった．

## VFM で確かめた段落の境界

表 1. VFM が段落を切る要素

| 要素 | 段落を切るか | 備考 |
|---|---|---|
| 空行 | 切る | 閉じ手の無いバッククォートは文字へ戻る |
| フェンス | 切る | 開いたままのコードスパンはそこで終わる |
| 行頭の `<!--` | 切る | HTML ブロックの開始として働く |
| ATX 見出し | 切らない | 空行を挟まない限り段落の一部になる |

最後の 1 行が CommonMark と食い違う．CommonMark では ATX 見出しが段落を
中断できる．VFM はそこから外れており，空行を挟まない `# 見出し` を段落の
一部として扱う．空行を挟めば `<section>` と `<h1>` が生成される．

本検査は「VFM が `{{errata}}` だけの段落を出すか」を予測するためのものである．
よって仕様ではなく VFM の実挙動へ合わせる．

## レビュー指摘の前提も成り立たなかった

Codex レビューは 2 ラウンドで 2 件の P2 を出した．判断は分かれた．

1 件目は「段落を切るブロックでコードスパンの状態を戻していない」である．
これは実在した．しかも自分が入れた変更による回帰であり，コメントの内側の
マーカーを本物と誤認する向きの誤りだった．案内が落ちたまま検査を通す方向であり，
PR #85 が防いだ失敗と同じ性質である．採用して直した．

2 件目は「ATX 見出しでも状態を戻すべき」である．前提が VFM で成り立たない．
指摘どおりに直すと，逆に指摘の例で誤って `true` を返すようになる．
見送ったうえで，指摘の例をそのまま回帰テストへ入れた．
判断を文章だけで残すと，次に同じ指摘が来たときに再び検証からやり直しになる．

同じ規律が 2 度効いた．**報告された前提は，Issue でもレビューでも実挙動で
確かめてから受け取る**．前提の出所が誰であるかは関係しない．

## 正解を機械で用意する

判断の裏取りには，VFM を正解とする突き合わせを使った．
各 fixture を VFM で描画し，`{{errata}}` だけからなる段落が出るかを正解とみなす．
これと `hasErrataMarker` の返り値を比べ，21 件で食い違い 0 件を確認した．

この検査は使い捨てとし，スクラッチパッドへ置いた．リポジトリへ恒久のツールを
足していない．ローカル linter を持たずクラウド CI を正とする方針に沿わせるためである．
`node_modules` の VFM は bare specifier で解決できないため，
`file:///` の絶対パスで直接読み込んだ．

## 代替案と棄却理由

Issue は「コメントの判定を原稿全体の文字列に対して行う」案も挙げていた．
これは採らない．行ごとのループはフェンスドコードブロックを先に処理しており，
その中の `<!--` をコメント開始と見なさない．全文へ `stripNonMarkup` を適用してから
走査すると，この振る舞いが壊れる．行間で状態を持ち回る案であれば構造を保てる．

見出しでも状態を戻す案は，前節のとおり VFM の実挙動と合わないため採らない．
