# 枠アイコン検査の種別導出で得た知見

Issue #190／PR #194 のセッションで得た知見を記す．
主な内容は 3 つある．検査対象を宣言から導く設計判断と，
検査をすり抜ける残り物への手当てと，レビュー指摘の受け取り方である．

## 目次

- 種別は定数でなく宣言から導く

- 残り物の検出と検査対象ゼロの扱い
- 観察は採り解決案は検証する

## 種別は定数でなく宣言から導く

`scripts/check-icon-bake.mjs` は検査対象を `BOX_TYPES` 定数で
固定していた．注釈枠を脚注化した派生書籍では実態と合わず，
`missing-source` の誤検出が出た（Issue #190）．

対応は，`theme.css` の `--<種別>-icon` 宣言から種別を導く形とした．
枠の構成が違う本でも，スクリプトへ手を入れずに検査が通る．
起票者の提案どおりの形であり，定数の差し替え口を設ける案より
caller の作業が少ない．

## 何を種別に数えるかの線引き

上流の `theme.css` 自身が，`--box-icon: var(--tips-icon)` という
集約変数を規則ごとにスコープして持っていた．名前の形だけで
`--*-icon` を拾うと，この集約変数が種別 `box` として混入する．

線引きは「線画のデータ URI を直接持つ宣言だけを種別に数える」とした．
`var()` 参照の集約変数は自然に外れる．名前の規約でなく値の実態で
判定する形は，命名の揺れにも巻き込まれにくい．

## 残り物の検出と検査対象ゼロの扱い

導出方式には従来と違う穴が 2 つある．いずれも黙って通る形なので，
機械検査の趣旨（黙認を許さない）に沿って先回りした．

- 種別を減らした本で，`print.css` に焼き済み変数だけが残る場合．
  電子書籍側は変わらず，紙面だけ古い絵柄が出る．`theme.css` に
  対応する宣言が無い `--*-icon-baked` を `missing-source` 違反とした．
- `--<種別>-icon` が 1 つも見つからない場合．検査対象ゼロのまま
  成功と表示すると，導出の壊れ方を隠す．この場合はエラーで止める．

## 観察は採り解決案は検証する

Codex レビューが P2 を 1 件出した．観察は「データ URI の認識が
二重引用符に限られ，単一引用符や引用符なしの残り物が検出を
すり抜ける」で，これは正当だった．

一方，添えられた解決案「値の書式を見ず名前だけで残り物を拾う」は
採れない．上流の `print.css` 自身が `--box-icon-baked: var(...)` の
集約変数を持ち，名前だけの照合ではこれを誤検出する．
認識パターンを 3 つの引用形へ広げる修正で観察へ応えた．
観察と解決案を分けて受け取る規律の適用例が，また 1 つ増えた．

## 上流で検証できない対応は実装しない

Issue の 2 点目（焼いた線画を 1 変数へ規則スコープで集約する
組み方への対応）は，上流へ実装しなかった．上流にその組み方の
実ファイルが無く，動作を検証する手段が無いためである．

代わりに，差し替えるべき箇所と参照先（派生書籍の PR #283）を
`detectBoxTypes` のコメントで案内した．検証できないコードを
持たない判断は YAGNI に沿う．必要になった本の側が，実物を
使って検証しながら差し替える方が確実である．
