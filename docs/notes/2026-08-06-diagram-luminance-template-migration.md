# 図版配色検査の汎用化移植で得た設計判断

`techbook-introduction-to-electronics-basic-led` で実装済みの図版 SVG 配色
（グレースケール輝度差）検査を，このテンプレートへ汎用化移植した作業
（Issue #53・PR #56）で得た設計判断とレビュー指摘の対応を記録する．

## 背景

- 書籍リポジトリ側で先に実運用され，効果が確認済みの検査だった．
  Issue #53 は移植手順（差し替え定数・トークン追加・初期状態の調整点）を
  具体的に整理済みで，設計判断はほぼ完了していた．
- 移植先のテンプレートは執筆前の初期状態で配布されるため，書籍リポジトリと
  異なり「検査対象の図版が 0 件」という状態を正しく扱う必要があった．

## 判断

- `DIAGRAM_TIER_COLORS`・`EXCLUDED_FILES` は移植元と同じく，本ごとに
  差し替え可能な定数として先頭に集約した．そのままの構成で移植できた．
- テンプレート同梱のサンプル `led-circuit.svg`（LED 発光を実体色の赤で
  表現）は `EXCLUDED_FILES` に含めた．実物色を再現する図は検査対象外に
  できるという既存の仕組みの実例を兼ねる．
- 実ファイル検証テストは，検査対象（除外リスト外）の図版が 0 件のとき
  `node:test` の `skip`（理由文字列付き）にした．新規プロジェクトの
  `npm test` を，図版を描く前の初期状態から赤くしないための調整である．
  書籍リポジトリ側は常に実図版があるため，この分岐は不要だった．

## レビュー指摘への対応

chatgpt-codex-connector のレビュー（P2 x3）と CodeQL（high x1）で，
移植元にも共通する検出すり抜け経路が見つかった．

- CSS プロパティ形式の色指定検出（`fill:` 等）が大文字小文字を区別して
  おらず，`FILL:#cc0000` のような表記ゆれで検査をすり抜けられた．
  正規表現へ `i` フラグを追加した．
- XML コメントを除去せずに色属性を走査しており，コメントアウトされた
  `fill` 等が誤検出・誤通過の双方を起こし得た．コメント除去を追加した．
- `--palette-diagram-annotation` の宣言検査が `css.includes()` の
  文字列一致だったため，宣言を削除してもヘッダコメント中の言及だけで
  すり抜けられた．CSS 変数を実際にパースして hex 値として解決できるかを
  検証するよう変更した．
- 上記のコメント除去（単発 `replace`）が CodeQL
  `js/incomplete-multi-character-sanitization`（high）に該当した．
  入れ子・破損したコメント境界で取り残しが生じ得るため，変化がなくなる
  まで繰り返す fixpoint ループへ修正した．検査の脅威モデルは「隠した
  違反を見逃さない（fail-closed）」ことであり，破損した入れ子コメントで
  色指定を隠しても `unregistered-chromatic` として検出されることを
  テストで固定した．
- いずれも移植元スクリプトに存在した潜在バグであり，本 PR ではテンプレート
  側のみ修正した．移植元（書籍リポジトリ）側への同様の指摘は別途起票が
  望ましい．

## 書籍リポジトリからテンプレートへの汎用化パターン

- 書籍リポジトリで実運用・効果検証済みの仕組みを Issue でテンプレートへ
  汎用化提案する運用が機能した．Issue 本文に移植手順が整理済みだった
  ため，設計判断のほとんどは Issue 時点で完了しており，実装は
  Sonnet（メインエージェント）で完結できた．Fable 5 へのエスカレーション
  は不要だった．
- 移植時に発見した既存バグ（本ノートのレビュー指摘 3 件）は，
  「そのまま移植」が思わぬ形で品質改善の機会になる例である．
  同種の汎用化 Issue では，レビュー・CodeQL を経由させることを前提にし，
  移植元への逆輸入（バックポート）の要否を都度判断するとよい．
