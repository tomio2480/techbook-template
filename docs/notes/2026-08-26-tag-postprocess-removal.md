# タグ付け後処理の廃止と再検討トリガ点検の記録

見送り済み Issue の再検討トリガを点検し，タグ付け後処理の廃止
（Issue #183・PR #184）へ至った経緯と知見を記録する．
測定の落とし穴と，上流調査で得た事実の切り分けを含む．

## 背景

オープンな Issue・PR が無い状態で次のタスクを探し，
「見送りで閉じた Issue の見直しトリガを先に読む」規律に従って
クローズ済み案件を点検した．Issue #26 の記録が残す再検討条件のうち，
「Vivliostyle CLI がタグ付き PDF を直接出力する」が引かれていた．
vivliostyle-cli#539 の修正は v8.16.1（2024-11-06）で入っていた．
導入済みの v8.20.0 はこの修正を含む．

トリガの記載より先にクローズしていた Issue を追跡先としていたため，
点検するまで 1 か月以上気づけなかった．追跡先の状態を，起票時でなく
点検時に確かめる必要がある．

## 判断

後処理（`scripts/tag-pdf.mjs`）を廃止し，直接出力を成果物とした．
理由は「不要になった」ではなく「有害になっていた」である．
直接出力のタグは原稿の DOM に由来し，原稿の画像 alt を
`Figure` の `/Alt` へそのまま運ぶ．後処理はこれをレイアウト解析の
推測タグで上書きし，alt を「image N」へ落としていた．

`@opendataloader/pdf` の依存は残した．`build:print`・`build:cover` の
検査がテキスト抽出（`--format text`）で使い続けるためである．
起票時は依存ごと削除する想定だったが，実装時の全参照走査で
タグ付け以外の用途が見つかり，Issue 本文を修正して範囲を絞った．

## 測定の落とし穴

Vivliostyle の出力を素のバイト列で走査すると，`/StructTreeRoot` は
0 件に見える．Catalog ごと圧縮オブジェクトストリーム（`ObjStm`）へ
入るためで，展開せずには存在しないように見える．
圧縮オブジェクトの取り逃しはページ数検査（Issue #145）と同根である．

2026-07-16 の調査ノートが「中間 PDF はタグなし」と記録したのは，
この落とし穴を踏んだ結果とみられる．PDF の構造を数えるときは，
必ずストリームを展開してから数える．「タグが無い」と「見えていない」
は，展開して初めて区別できる．

## 上流調査で得た事実

`opendataloader-pdf` の alt スキーマ統一（上流 PR #537）は，
JSON・Markdown・HTML の出力側の変更である．タグ付き PDF の
`/Alt` には効かない．同じ「alt の改善」でも，どの出力層の話かを
切り分けないと，再検討トリガの発火を誤判定する．
外部から alt を与える入力は v2.5.5 時点でどの層にも存在しない．

## 代替案と棄却理由

表 1. 検討した代替案と棄却理由

| 案 | 棄却理由 |
|---|---|
| 後処理を opt-in で残す | 直接出力に対する利点が無く，Java 依存と 4 分ビルドの延長だけが残る |
| `@opendataloader/pdf` の依存ごと削除 | 紙入稿・表紙の検査のテキスト抽出が壊れる．範囲を後処理の廃止に絞った |
| タグ有無の機械検査を同 PR に含める | PR を小さく保つため分離し，Issue #185 として起票した |

## レビューでの学び

README の使い方節に残った旧手順の記述を Codex に指摘された．
機能語（「タグ付き」「Java」等）で grep して洗い出したつもりが，
「アクセシビリティタグを付与」という言い換え表現の段落を逃した．
参照の洗い出しは機能語だけでなく，削除対象のファイル名
（`tag-pdf`）でも全文を再走査し，両方の結果を突き合わせる．
