# 奥付への著者紹介・正誤表リンク流し込みの設計判断

奥付へ著者紹介と正誤表リンクをデータから流し込む実装（PR #54）で得た

## 背景

- 奥付の著者紹介・正誤表リンクを手書きすると，書籍間で体裁がばらつき，
  記載漏れが起きる．データと体裁の分離が要求だった．
- 要求・要件は `docs/spec/colophon.md` に固定した．本ノートは設計（how）の
  記録であり，spec とは役割を分ける．

## 判断

- 流し込みは rehype プラグイン（`scripts/inject-colophon.mjs`）で行う．
  原稿に単独段落のマーカー（`{{authors}}`・`{{errata}}`）を書き，
  ビルド時に hast ノードへ置換する．
  既存の `joinCjkLineBreaksPlugin` と同じ組み込み方式のため，
  ビルドパイプラインへの追加コストが小さい．
- データ欠損時はマーカーを残さず取り除き，警告を出す．
  出版物へ `{{authors}}` の文字列が残る事故の防止を最優先にした．
- 上下分割レイアウトは flex で組む．奥付 body は既存の
  `justify-content: flex-end` を保ち，著者紹介へ `margin-bottom: auto` を
  与えて上部へ寄せる．マーカーがタイトル見出しの後ろへ置かれた場合は
  `:has()` で section 側を flex 化して同じ挙動にする．
- 発行履歴（`YYYY年MM月DD日 第N版第N刷発行`）は手書きとする．

## 代替案と棄却理由

- 奥付 Markdown を丸ごとスクリプト生成する案は棄却した．
  手書き部分（印刷所・連絡先等）と生成部分が同居するため，
  生成のたびに手書き部分を壊すリスクがある．マーカー置換なら
  手書き部分へ一切触れない．
- テンプレートエンジン（Mustache 等）の導入は棄却した．
  依存が増えるわりに置換対象が 2 つしかなく，KISS に反する．
- 発行履歴を `errata/errata.yml` の editions から自動生成する案は
  棄却した．editions は刷（printing）を管理しておらず，スキーマへ
  刷を足すと公開正誤表サイトの収集側（errata-ops）へ影響が及ぶ．
  クロスリポジトリの変更を避け，手書き運用とした．

## 詰まった箇所

- 奥付 h1 の `break-before: page` が残ったまま書籍タイトルを
  ページ途中へ移すと，タイトル以降だけが次ページへ割れる．
  先頭要素にしか効いていなかった指定が，要素の移動で顕在化する
  パターンであり，レイアウト変更時は break 系プロパティを再点検する．
- VFM は最初の見出しより前の内容を section の外（body 直下）へ置く．
  マーカーの位置により置換結果の DOM 階層が変わるため，
  CSS は body 直下・section 内の両方の配置へ対応させた．

## 検証手段の制約

- この環境には `pdftoppm` が無く，ブラウザペインも PDF の file:// 表示で
  応答しなかった．PDF の見た目の最終確認はユーザーの目視に委ね，
  Claude 側は生成 HTML の構造検証（セレクタが効く DOM か・マーカー残存や
  目次への見出し混入が無いか）で代替した．
- 構造検証だけでも「レイアウト CSS が効く前提条件」はほぼ確認できる．
  PDF レンダリング環境が無い場合の実務的な代替として有効だった．
