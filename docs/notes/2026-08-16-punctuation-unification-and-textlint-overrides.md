# 句読点の統一と textlint overrides が無効だった件

README と原稿の句読点を「．」「，」へ統一した際の判断と，
その過程で見つかった textlint の `overrides` が効いていない事実を記録する．
対象は Issue #90・#98・PR #101・#102・#105 である．

## 背景

- 句点を「．」へ統一した #75 は読点に触れていなかった．
  README の初期からある節に読点「、」が残っていた（#90）．
- サンプル原稿は句読点が「。」「、」のままで，`CLAUDE.md` の方針と食い違っていた．
  #89 が「別途扱う」と記したままクローズされ，受け皿が無かった（#98）．
- 読点の字種を判定する textlint 規則が無く，CI では見つからない（#99 へ切り出し）．

## 判断

### コードフェンスとインラインコードの内側は触らない

置換はフェンス外の地の文・箇条書き・引用に限った．インラインコードと
`$…$` 数式は退避してから置換した．設定例（`book.yaml` の `notice`）や
Markdown 記法の例が対象から外れるのは意図どおりである．
例示は実出力と一致させる方針（2026-08-13 のノート）と同じ考えである．

### 置換のついでに直す範囲を絞る

同じファイルにあった半角と全角の間隔の指摘 8 件は直した．
機械的で判断が要らず，派生リポジトリの執筆者へ残す理由が無い．

一方で次は触らず，Issue へ切り出した．

- 表キャプションの句点（8 件）: 上流 #57 が「キャプションは体言止め」と決めた．
- 奥付の発行履歴の行（8 件）: `docs/spec/colophon.md` の形式との衝突（#104）．
- 表示数式 `$$` の文長（2 件）: 数式を文として数える誤検出（#104）．
- 奥付へ注入する案内文・設定サンプルの「。」: スクリプトとテストを触る（#103）．

## textlint は overrides を読まない

`.textlintrc.json` の `overrides` で `src/chapters/**` をですます調と
宣言していた（#89）．手元実行ではですます調の章へ `no-mix-dearu-desumasu` が
16 件出た．調べたところ，textlint 15.6.0 に `overrides` の実装が無かった．

- `@textlint/config-loader` の型は `plugins`・`filters`・`rules` の 3 キーのみ．
- `node_modules/textlint`・`node_modules/@textlint/**` に `overrides` の文字列は無い．
- 最小構成（1 ファイル＋設定）でも再現し，`files` を `**/*.md` に広げても，
  `overrides` 側で preset を `false` にしても結果は変わらなかった．

上流へ `tomio2480/github-workflows#85` を起票し，v2.6.11 で案内が撤去された．
本リポジトリは #105 で `overrides` を外した．ですます調の 4 章には
frontmatter の直後へ `textlint-disable` のコメントを置いた．
生成 HTML ではコメントとして残るだけで，本文を巻き込まないことを確認した．

## CI の緑は検証にならない

`overrides` が動くと信じられていた根拠は「設定を入れた PR で CI が通った」だった．
しかし composite action の既定は `filter-mode: added`・`fail-on-error: false` である．
差分行以外の指摘は表に出ず，指摘があっても job は成功する．
原稿を触らない PR では，原稿への指摘が何件あっても見えない．

lint 設定の効き目を確かめるときは，次のいずれかで裏取りする．

- 一時領域へ同じ版を入れて実行し，件数を見る．
- 意図的に違反する行を差分へ含め，指摘が出ることを見る．
- 断定の前に，パッケージ内で当該キーの実装を検索する．

## 運用面の観察

- 中央テンプレートの依存は composite action の `package.json` に固定されている．
  同じ版を入れれば，手元の件数と CI の Lint summary は一致した．
- 句読点を変えるとですます調の章の全文が差分行に乗り，隠れていた文体の指摘が
  inline コメントとして一斉に出た．差分の少ない PR ほど指摘が隠れる．
- 上流への起票から v2.6.11 のリリースまでは同日中だった．
  発生源で直すと，追随は SHA バンプとコメント 2 行で済んだ．
- ビルドは `toc.html`・`vivliostyle.config.js` の改行コードだけを変えることがある．
  コミット前に `git status` を見て復元する．
