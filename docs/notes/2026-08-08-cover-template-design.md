## 🔍 背景

表紙は文字だけの簡素なページで，裏表紙はバーコード配置の受け皿のみ
だった．入稿品質の表紙・裏表紙をテンプレートから作れるようにした．
文字は画像化せず，背景画像の上へ実テキストで重ねる方針である．

## 🛠 判断

### 背景はページ背景（@page）で敷く

背景画像は `@page` の `background-image` で敷いた．DOM に画像要素を
置かないため，PDF の論理構造へ装飾が混入しない．`body` に敷く案は
本文の高さがページに満たないと背景が途切れるため採らなかった．
ページコンテキストの `var()` は `:root` の値を解決できる．
既存の柱（`--running-head-color`）で動作実績があることを根拠にした．

### 表紙と本扉の分離と文字列の単一供給

表紙（デザイン面）と本扉（簡素なタイトルページ）を分離した．
書名・著者名は `config/book.yaml` を単一の出所とし，マーカー
（`{{book-title}}` 等）で両ページへ流し込む．体裁は表紙側だけを
CSS 変数で可変にし，表紙のデザイン調整が本扉へ波及しない状態を保つ．

### マーカーの 2 方式を使い分ける

ISDN 系は単独段落マーカー（置換漏れが出力に残らない設計）．
書名系は見出しや文中への埋め込みが用途のためインライン置換とした．
インライン置換はコード文脈（`code`・`pre`・`script`・`style` 等）の
除外が必須である．作例のマーカー文字列を書き換えてしまうためである．

### サンプルデータ同梱と差し替え忘れの機械検出

見た目をビルド直後から確認できるよう，サンプル番号とダミーの
バーコード画像を同梱した．出版事故を防ぐ検出は 2 系統に分けた．
番号はサンプル値との一致，画像は SHA-256 ダイジェストとの一致で
独立に警告する．番号だけを差し替え完了の信号にしない（Codex P1）．

## 💡 詰まった箇所・レビューでの学び

**VFM の class は html と body の両方へ付く**．frontmatter の
`class: back-cover` は `<html>` にも付与される．クラスセレクタ
（`.back-cover`）へ `padding` を書くと html と body で二重適用され，
裏表紙が 1 ページに収まらず 2 ページ化した．余白系プロパティは
`body.<class>` 限定のルールへ書く．ページ数の機械カウント
（PDF 内の `/Type /Page` 走査）が安価な回帰シグナルとして働いた．

**数字抽出による正規化は値を改変する**．価格の `[^\d]` 除去は
`1000.50` を `¥100050E` に変えてしまう（Codex P2）．出版物へ載る値は
「検査して不正なら載せず警告」が正しく，救済的な正規化は危険である．

**前付けページの追加は目次除外リストの更新を伴う**．本扉の追加で
自動目次に「書籍タイトル」が混入した．`TOC_EXCLUDED_HREF_PATTERNS`
（`scripts/add-line-numbers.mjs`）への追加が必要である．

**README の句点は中央 textlint と衝突している**．README は全文「。」
統一だが，中央設定は「．」を要求する．追記行だけ直すと混在するため
見送り，方針整理を Issue #72 へ分離した．

**バーコードの規定位置は綴じ方向に依存する**．商業書籍の慣行
（表 4 左上）をそのまま流用したが，左綴じ前提では右上が適切との
指摘を受けた．慣行の移植では前提条件（綴じ・開き）の確認を先に行う．
