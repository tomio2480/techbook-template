## 背景

- 4 件はいずれも派生リポジトリ側の作業で見つかり，発生源である
  テンプレートへ Issue として起票されていた．
- 作業中に PR #88 がマージされ，ルートへ `.textlintrc.json` が入った．
  4 本とも `main` へリベースして取り込んだ．
- 検査スクリプトの修正 3 件は TDD で進めた．先に Red を確認してから
  実装する手順を守った．

## 判断

- **除外リストの実在検査は残す**．Issue #82 は図版 0 件のとき検査を
  省略する案だったが，テンプレートは唯一の図版を除外しているため，
  その条件では検査が永久に眠る．実在する図版の総数で省略を判定する．
- **価格のカンマは位置まで見る**．カンマを除去してから数字列を検査
  すると `1,,000` や `10,00` を通す．3 桁区切りの形を正規表現で直接
  検査する方式へ改めた．
- **正式名称は崩さない**．漢字連続の指摘を言い換えで解消していたが，
  国際標準同人誌番号は `isdn.jp` が示す正式名称であり，崩すと別物を
  指す．`max-kanji-continuous-len` の `allow` へ登録して通す．

## HTML コメント判定の二層問題

まえがきの `{{errata}}` 検査は，マーカーが段落になるかどうかを見る．
判定には 2 つの層があり，片方だけでは誤る．

- 第 1 層は Markdown の構文である．HTML ブロックは `-->` を含む行で
  終わり，その行全体がブロックの一部になる．
- 第 2 層は出力された HTML である．終了行の後ろに `<!--` が続けば，
  マーカーは段落になっても，誌面では読者へ届かない．

Codex の指摘はこの第 2 層を突いていた．終了と同時に走査を打ち切ると
`--> <!--` を取りこぼす．区切りを出現順にたどって状態を反転させる
方式へ改め，両方の層を満たすようにした．

逆にインラインコードやエスケープの中の区切りは実体参照へ落ち，
コメントを開かない．文字列一致で拾うと本物のマーカーを見落とし，
偽の警告を出す．走査の前にこれらを取り除く必要がある．

## textlint を手元で再現する

本リポジトリはローカル linter を持たず CI を正とする．
ただし reviewdog の PR コメントは 20 件で打ち切られ，Actions ログにも
差分行の指摘しか残らない．全体像を掴めず往復が増える．

対処として，作業用の一時領域へ中央テンプレートと同じ設定と依存を
置き，そこから対象ファイルだけを検査した．40 件から 0 件まで 3 回で
収束した．リポジトリへ設定を足していないため，CI を正とする方針は
崩していない．

`prh` の `rulePaths` は設定ファイルからの相対で解決される．
ルートの `.textlintrc.json` をそのまま使うと `prh.yml` を見つけられ
ないため，設定ごと一時領域へ写して実行した．

## ドキュメントの例示は実出力と一致させる

textlint の半角全角スペース指摘を空白挿入で直すと，付録の図番号の
例が `図 A.-1` になった．テーマ CSS は `図A.-1` を生成するため，
読者は存在しない出力を信じることになる．

規則を満たすためだけに例示を書き換えてはならない．インラインコード
で囲めば，実出力のまま規則も満たせる．

## 運用面の観察

- 4 本は互いに独立しており，リベースとマージのどちらも競合しなかった．
  Issue ごとに PR を分けた判断は，レビューと差し戻しを局所化した．
- Codex は 4 本中 2 本で指摘を出し，いずれも実在する穴だった．
  自動レビューは無効設定のため，`@codex review` の投稿で起動する．
- 中央テンプレートからの逸脱は `allow` の 1 点だけである．
  逸脱の理由は設定ファイルの `_comment` へ書き残した．
