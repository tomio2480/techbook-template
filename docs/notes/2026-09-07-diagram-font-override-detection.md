# 図中の書体を覆す一括指定の検出と，走査範囲の綱引き

図中フォント検査が `font` 短縮記法を見逃していた（Issue #217）．
塞ぐにあたり，値を解析せず一括指定そのものを違反とする方針を採った．
検出を広げると誤検出が増え，範囲を狭めると見逃しが増える．
その綱引きを，レビュー 3 巡と変異 11 種で詰めた記録である．
前提が実測で外れた例と，通っているだけのテストを踏んだ例も残す．

## 背景

`scripts/check-diagram-fonts.mjs` は `font-family` の属性と宣言だけを走査していた．
CSS の `font` 短縮記法で書体を指定すると，未登録のフォントが描画へ使われても
違反にならない．派生本の作業で Codex が指摘し，上流へ起票した．

## 実測でわかった覆り方

書き方ごとに，root の `font-family` を覆すかを Chromium で測った．
root へ `font-family="Verdana, sans-serif"` を置き，`getComputedStyle` で読む．

表 1. 書き方ごとの覆り方

| 書き方 | 適用された書体 | root を覆すか |
|---|---|---|
| `<style>` 内の `font: 20px Courier` | Courier | 覆す |
| `style="font: italic 12px Papyrus"` | Papyrus | 覆す |
| `@media screen` に包んだ `font` 宣言 | Courier | 覆す |
| 2 つ目の `<style>` の `font` 宣言 | Impact | 覆す |
| `font="20px Impact"` 属性 | Verdana | 覆さない |
| `all: initial` | 既定フォント | 覆す |
| `all: unset` | Verdana | 覆さない |
| `all: revert` | Verdana | 覆さない |

`font` 属性は Chromium が無視する．
`all` は `initial` のときだけ覆る．CSS Cascade 3 が継承プロパティに対する
`unset` を `inherit` と定めるためである．`font-family` は継承プロパティである．

測り方は最小構成が速い．`dist/` へ単一の HTML を置き，
プロジェクト内のパスを in-app browser で開いて `getComputedStyle` を読む．
プロジェクト外のパスは静的スナップショットになり，スクリプトが動かない．

## 判断: 値を解析しない

短縮記法の値から書体だけを取り出す解析は誤りやすい．
`font` の値は省略可能な要素を並べる形で，family は末尾に来る．
`all` の値は CSS 全域キーワードで，`initial` だけが覆る．

どちらも「値を読んで場合分けする」経路を持たない方針を採った．
プロパティ名を見つけたら一律に違反とする．
図版では `font-family` と `font-size` を分けて書く規約とし，短縮記法を使わせない．

この方針では，誌面の書体が変わらない場合まで報告する．
`font` 属性と `all: unset` が当たる．それでも報告する理由は 2 つある．
指定したつもりの書体が出ない状態を残さないこと．
値で場合分けすると，避けたはずの値の解析へ戻ることである．

検査の見逃しは規約の空文化に直結する．
規約を機械で守れない形にすると，注記が残るだけになる．

## 走査範囲の綱引き

検出を広げた直後，Codex が誤検出を 2 件挙げた．どちらも再現した．

1 件目は本文の文字列である．走査対象が `<style>` を外しただけの全文であった．
`<text>ここへ font="20px Impact" と書く</text>` のようなラベルを属性と誤認する．
同じ誤検出は既存の `font-family` 走査にもあった．

2 件目は at-rule の条件部である．`@supports (all: initial)` の条件を宣言と誤認し，
値も `initial) { .l { fill: black` のように壊れて出る．

対処として走査を 2 か所で狭めた．
属性は開始タグの中だけを見る．宣言は at-rule の前置きを外してから見る．

**狭めると今度は見逃しが怖くなる．** 検査にとって見逃しは誤検出より危ない．
誤検出は書き手が気づくが，見逃しは誰も気づかない．
そこで開始タグの形を回帰テストで固定した．
自己終了タグ・名前空間付きのタグ名・属性値に `>` を含むタグ・改行をまたぐタグである．

除去の順序にも落とし穴がある．コメントを先に外す．
逆にすると，コメント内の `@` が前置きとして後続の宣言まで飲み込む．
`style` 属性は `{` と `;` を持たないため，値の末尾まで消える．

## レビューで得た 3 つの型

### 型 1: 報告された前提は実測で確かめる

副担当は `all: initial` `all: unset` `all: revert` の 3 つとも覆ると書いた．
測ると覆るのは `initial` だけであった．
提案そのものは正しく，前提の範囲だけが広すぎた．
確かめずに 3 つとも「覆る」と書いていたら，誤った記述が残った．

### 型 2: 通っているだけのテストは変異で洗う

順序を守るテストを書いたが，変異を当てても落ちなかった．
`<style>` ブロック内では `{` が壁になり，順序を逆にしても宣言が生き残る．
`style` 属性を使う形へ書き直して判別できた．

同じ失敗を複数行の at-rule でも踏んだ．
条件を `@media screen and (min-width: 30em)` で書くと，
走査が改行で止まる変異を当てても落ちない．
止まった後に残る文字列が，宣言らしい形をしていないためである．
条件を `@supports (font: menu) and (all: initial)` へ替えて判別できた．

**テストを足したら変異で洗う．** これを手順として固定する．
落ちるべきテストが落ちないなら，そのテストは何も守っていない．

### 型 3: 観察と結論を分けて受け取る

セルフレビューが，at-rule 絡みの既存テスト 3 件を
「前置き除去が無くても通る」と挙げた．観察は正しい．
だが「何も守っていない」という結論は当たらなかった．

逆方向の変異を当てると 3 件とも落ちる．
前置きの走査が `{` を越えてブロックの中身まで消す形である．

表 2. 変異の方向と落ちるテスト

| 変異の方向 | 落ちるテスト |
|---|---|
| 前置き除去を丸ごと外す（止まらなさすぎ） | 複数行のテストほか 3 件 |
| 前置きが `{` を越える（行きすぎ） | 既存 3 件を含む 5 件 |

既存 3 件は行きすぎの方向を守っていた．
1 つの変異で落ちないことは，そのテストが無価値である証拠にならない．
守る方向が違うだけのことがある．

## 代替案と棄却理由

- **短縮記法から family を解析して同じ判定にかける．** Issue が挙げた案である．
  既存の書き方を壊さない反面，値の文法を自前で辿る必要がある．
  誤判定は検査のすり抜けに直結するため採らなかった．
- **`all` は README への注記だけに留める．** 副担当の提案である．
  覆る経路が実在する以上，機械で守れない規約が 1 つ増えるため採らなかった．
- **XML と CSS を構文として解析する．** 依存を増やす割に，
  このスクリプトが必要とするのは開始タグと宣言の範囲だけである．
- **整形式でない SVG を fail-closed にする．** `<style>` の閉じ忘れなどで
  0 件通過になる性質は，このスクリプト全体に元からある．
  今回の 2 経路に固有の後退ではないため，別 Issue へ回した．
