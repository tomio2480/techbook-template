# 回り込みのタグ読み順検証とキャプション可視化の判断

Issue #204・#205 のセッションで得た知見を記す．
回り込み（`figure-wrap`）でタグ付き PDF の読み順が乱れないことを
実測で確かめ，原稿へ使用例を常設した．あわせて VFM 生成
figcaption の aria-hidden を外さない判断とその根拠を記録する．

## 回り込みの読み順は原稿順を保つ

`figure-wrap` は図を `float` で右へ寄せ，本文を脇へ流す．
視覚上の配置が変わっても，構造ツリーの並びは原稿の記述順のまま
だった．最小構成と実書籍（`03-math-and-figures.md` へ追加した
使用例）の両方で確認した．並びは次のとおりである．

1. 回り込みの前の段落
2. Figure（`/Alt` はキャプションの文字列）
3. 内側の Figure（`/Alt` は画像の alt）とキャプション本文
4. 回り込ませた本文の段落（記述順）
5. 枠を抜けた後の段落

キャプションは可視のため本文としてタグ付けされ，CSS 採番の
接頭辞（`図 3.2.3.-1:` など）も読み上げの対象に含まれる．
veraPDF の検証でも，使用例の追加による未マーク内容の増加は無い．

2026-08-20 のノートが残した宿題（回り込みと読み順）は，
これで解消した．

## 検証の方法

構造ツリーを読み順で辿り，各要素の型・`/Alt`・本文を並べて出す．
本文は marked-content の MCID を内容ストリームと突き合わせ，
ToUnicode で復号して得る．要点は次のとおりである．

- 構造ツリーの K 配下を再帰で辿ると，木の並びが読み順になる．
- MCID → テキストの表はページごとに作る．検証した PDF の
  フォントは Type3 で，符号は 1 バイトだった．
  ToUnicode CMap（bfchar・bfrange）から文字へ引く．
- 検証は使い捨てスクリプトで行い，恒久ツールは新設しない．

## キャプション可視化は採らない

Issue #203 で，VFM 生成 figcaption（`aria-hidden="true"`）の描画が
未マーク内容 34 件になると判明した．aria-hidden を外せば解消する
（最小構成で確認．可視キャプションの未マークは 0 件になる）．

それでも現状維持を採る（Issue #205）．VFM 生成の図では
「キャプション＝画像 alt＝figure の `/Alt`」がすべて同一の
文字列である．可視化すると同じ文が最大 3 回読まれる形になり，
読み上げの体験を悪化させる．VFM が aria-hidden を付けるのは
この重複を抑える意図であり，尊重する．

- 読み上げは #197 の前処理が figure の `/Alt` へ写して確保済み．
- 残る未マーク 34 件は，Chromium が aria-hidden の描画を
  Artifact にしない上流挙動によるもので，分類ノートの
  上流由来群と同じ機序である．

## 派生書籍への案内

`techbook-introduction-to-electronics-basic-led` は回り込みを
既に使っている．本検証により，回り込み部分の読み順は原稿順の
まま保たれるため，タグ読み順の観点での対処は要らない．
読み順を確かめたいときは，本ノートの方法で構造ツリーを辿る．
