# 組版の変更をどう確かめるか

テーマ CSS へ改ページと図の配置の規則を足した．
PR #149（Issue #129）と PR #151（Issue #128）である．
本稿は，その過程で定まった検証手段と，途中で捨てた検証手段を残す．
結論を先に書くと，**組版位置は PDF ではなく Vivliostyle Viewer から読む** ．

## 目次

- 変更の内容
- 検証手段の選定
- 捨てた検証手段
- 設計の判断
- 次に同じ場面へ出会ったら

## 変更の内容

2 件とも派生リポジトリの実運用から上がった要望である．

- `ol` へ `break-inside: avoid` を与え，番号付きリスト全体の分断を抑える．
  目次では `break-inside: auto` で除外する．
- `.figure-row` で図を横へ並べ，`.figure-wrap` で本文を回り込ませる．
  どちらも `figure` を 1 段深くするため，採番セレクタへ枝を足す．

## 検証手段の選定

組版の変更を確かめるには「どの要素がどのページへ入ったか」を知る必要がある．
PDF を経由せず，Vivliostyle Viewer をそのまま読む方法へ落ち着いた．

Viewer の実体は `node_modules/@vivliostyle/viewer/lib/index.html` にある．
これを `playwright-core` で開く．
`window.coreViewer.readyState` が `complete` になるまで待つ．
そのうえで `#vivliostyle-viewer-viewport` 配下のページ容器を数える．

```js
[...document.querySelectorAll(
  '#vivliostyle-viewer-viewport > div > div > div[data-vivliostyle-page-container]'
)].map(container => container.textContent ?? '')
```

この方法には次の利点がある．

- **生成内容を読める．** Vivliostyle は `::before` の内容を DOM へ実体化する．
  図番号やリストの採番を，組んだ結果の文字列として取り出せる．
- **座標を測れる．** `getBoundingClientRect()` で図と本文の位置関係が分かる．
  回り込みの判定では `Range` の行ごとの矩形を使う．
  ブロックの箱は回り込みでも版面幅のままであり，行を測らないと判定できない．
- **速い．** PDF の書き出しを挟まないため，1 回あたり数十秒で終わる．

起動には 2 つの注意が要る．

- `playwright-core` の既定は `headless_shell` を使うが，本環境には入っていない．
  `chromium-1161/chrome-win/chrome.exe` を `executablePath` へ渡して起動する．
- 参照先の原稿が無いと `target-counter` が解決できず，描画が終わらない．
  目次だけを切り出して試すときは `href` を自ページへ向ける．

## 捨てた検証手段

### PDF のバイト列の比較

出力の md5 が変われば組版が変わった，という判定は成り立たない．
同じ入力で 2 回ビルドすると md5 が変わる．
最初この判定を使いかけ，同一入力の 2 回ビルドで否定した．
**判定の根拠へ使う前に，判定そのものを試す．**

### PDF のテキスト抽出

`@opendataloader/pdf` の `--format text` は箇条書きを取りこぼす．
12 個のリストのうち 6 個しか出力されなかった．
図の中の文字も落ちる．紙面の中身を数える用途には向かない．

皮肉なことに，孤立した 1 項目は「リストではない段落」と判定されて抽出される．
そのため今回の分断解消は，抽出結果から項目が消えることで確認できた．
狙って使える性質ではない．

あわせて，抽出結果は漢字が康熙部首（`⽂`・`⼿`）へ置き換わる．
語で照合するなら `NFKC` で正規化してから比べる．

### ページ数だけの比較

1 つのリストの分断は，ページ数へ現れない．
分断されても，まとめて次ページへ送られても，総ページ数は変わらないためである．
リストを 16 個並べて初めて差が出た（17 ページが 18 ページになった）．
**変化が出る密度まで詰めたフィクスチャを作る．**

## 設計の判断

### 目次の除外は測れなくても残す

`ol` の分断抑止を目次から外す指定は，本テンプレートでは効果を測れなかった．
除外あり・なし・変更前の 3 通りが同じページ数になる．
既存の `li { break-inside: avoid }` が章のまとまりをすでに保っている．
最上位の `ol` は 1 ページに収まらないため，分割へ倒れるのだろう．

それでも残した．派生リポジトリで実害が観測されていること，
組版の規律が目次の除外を定めていること，除去の利得が小さいことによる．
**測れないことは，要らないことと同じではない．**

### 回り込む図には既定の幅を与える

Issue の案には図の幅指定が無かった．足した理由は実測にある．

幅を与えない `float` は shrink-to-fit となり，最大幅は中身で決まる．
短い英文キャプションでは図が細いままで問題が出ない．
一方，**和文のキャプションは分割点が少なく，枠が版面のほぼ全幅まで広がる** ．
このとき本文の帯が消え，回り込みが成り立たない．

| キャプション | 図の左端 | 本文の行末 |
|---|---|---|
| 英文（短い） | 483pt | 467pt（回り込む） |
| 和文（長い） | 108pt | 620pt（回り込まない） |

英文だけで試すと見落とす．**和文の紙面は和文で試す．**

### 付録の採番は別の枝が要る

付録の図番号は `.appendix section.levelN > figure` で定義されている．
新しいクラスは `figure` を 1 段深くするため，この規則から外れる．
外れると本文用の規則が当たり，章番号が英字にならない．
番号が消えるのではなく，誤った番号を出す点で厄介である．

同じ形の欠落が `.column`・`.tips` にもある．
付録のコラム内の図は `図2.1.-3` のように算用数字で出る．
本 PR の変更とは独立した元からの不具合であり，Issue #150 として切り出した．

### 残した宿題

回り込みがタグ付き PDF の読み順へ与える影響は測っていない．
テンプレート本体の原稿が新しいクラスを使わないため，
実際に組んだ紙面でタグを確かめる機会が無かったためである．
`docs/spec/pdf-tagging.md` は読み順の自動検出が完全でない旨を既に記している．
派生リポジトリで回り込みを使うときは，タグの並びを確かめておきたい．

## 次に同じ場面へ出会ったら

- 組版の位置を知りたいなら Viewer を読む．PDF は最後の確認に使う．
- 差が出ないフィクスチャは，条件が緩いことを疑う．密度を上げて作り直す．
- 変更前に測り，狙った箇所だけが変わったことを確かめてから足す．
- 和文特有の性質（分割点の少なさ）は，英文の試験では現れない．
