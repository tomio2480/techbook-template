# README の scripts ツリーを全数掲載へ引き直した記録

`scripts/` の見取り図が非網羅であった件を直した経緯をまとめる．
絞る基準を決めるより先に全数を載せる判断へ至った理由と，
「呼び出しが見つからない」を実行されていない証拠と読み違えた失敗を記録する．

## 背景

`scripts/` はテストを除いて 21 本ある．README のツリーは 13 本しか載せていなかった．
載っている顔ぶれに理由が無く，読み手は「載っていない＝無い」と受け取りうる．
Issue #172 はこの点を挙げ，基準を決めて引き直すことを求めていた．

Issue は 2 案を示していた．全数を載せる案と，基準を決めて絞る案である．
起票の時点では後者を推していた．利用者が触るのは `npm run` の側だという理由による．

## 判断

### 全数を載せたうえで 2 群に分ける

絞る案は採らなかった．基準を書いても，線の外にあるものは見えないままである．
見取り図の役目は構成を示すことであり，何が無いかを隠すことではない．

全数を載せ，並びを 2 群へ分けた．基準はツリーの直前へ 1 行で書いた．
長いツリーの途中から読む者にも届くよう，`scripts/` の行にも短く残した．

<!-- textlint-disable ja-technical-writing/ja-no-mixed-period -->

表 1. ツリーの 2 群と本数

<!-- textlint-enable ja-technical-writing/ja-no-mixed-period -->

| 群 | 中身 | 本数 |
|---|---|---|
| 前半 | 単体で実行の入口を持つもの | 15 |
| 後半 | 他のスクリプトから `import` される部品 | 6 |

### 群の分け方は実装から決めた

`argv[1]` を見る主処理を持つかどうかで，21 本が 15 本と 6 本へきれいに分かれた．
分類を先に決めてから当てはめると，境界の事例で判断が揺れる．
実装の側に自然な切れ目があるなら，それを使う．

引き直す前のツリーは，この区別でも `npm script` の有無でも説明が付かなかった．
部品である `print-layout.mjs` と `count-pdf-pages.mjs` が載り，
単体で実行できる検査 5 本が漏れていた．

## 外した見立て

作業の途中で「呼ばれていない検査が 3 本ある」と報告した．これは誤りである．

挙げたのは次の 3 本である．

- `check-contrast.mjs`
- `check-diagram-luminance.mjs`
- `check-gradient-hardstops.mjs`

いずれも `package.json` の `scripts` に無く，ワークフローからも呼ばれない．
`grep` で呼び出し箇所を探し，見つからないことを根拠にした．

実際は各 `*.test.mjs` が実ファイルへの回帰検査を持つ．
`palette.css`・`theme.css`・`src/assets/diagrams/*.svg` を直接読み，
違反が 0 件であることを確かめている．
`npm test` から，CI の test ジョブが毎回この検査を走らせる．
README の「スクリプトのテスト」節にも，その旨が書いてあった．

**呼び出しが見つからないことは，実行されていない証拠にならない．**
実行の経路はテスト・設定ファイル・プラグイン登録にも通る．
別の経路を当たらないまま，欠落として報告してはならない．

## 検査の再現

textlint を手元で再現する手順は既存の記録が扱う．
ここでは，組み直しで詰まった点だけを足す．

### 前のスクラッチパッドは再利用できない

過去のセッションのスクラッチパッドに `node_modules` が残っていた．
ディレクトリは辿れるが，中のファイルは消えている．
`ls` が成功するため，壊れていることに気づきにくい．

使う前に，再帰的なファイル数を数える．0 件なら作り直す．

### 中央は pin 済みの SHA で clone する

設定を 1 本ずつ取得するより，中央のリポジトリを clone するほうが速い．
`md-lint.yml` が pin する SHA を使えば，CI と同じ版がそろう．
`scripts/`・`templates/`・composite action の `package.json` が一度に手へ入る．

依存は action の `package.json` と `package-lock.json` を写して `npm ci` する．
中央の `install-textlint-deps.sh` と同じ経路であり，版の指定を自分で書かずに済む．

### 規則が生きていることを fixture で確かめる

対象のファイルが 0 件だったとき，2 つの可能性が残る．
本当に指摘が無い場合と，規則が読まれていない場合である．
依存の欠落で全 rule が黙って捨てられる事例が，中央の記録に残っている．

文体・読点・句点の違反を故意に書いた `.md` を 1 本作り，同じ設定で走らせた．
3 件を検出したため，規則は生きていると確かめられた．
0 件を報告の根拠に使うなら，この 1 手を毎回挟む．
