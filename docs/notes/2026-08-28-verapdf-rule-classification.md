# veraPDF 失敗ルールの分類と上流報告の要否

Issue #197・#198 の対応後も残る veraPDF（PDF/UA-1）の失敗を分類する．
残る 5 ルールの帰属（上流由来・意図した非宣言）と根拠を記す（Issue #199）．
7.1-3 の全 349 件の内訳と機序は Issue #203 の解析で確定した．
上流の既知 Issue の確認結果と，報告見送りの判断も記録する．

## 分類の全体像

分類は PR #200（#197）と PR #201（#198）のマージ後の状態で行う．
CI の検証レポート（run 33128813282）は
失敗 5 ルール・759 チェックを報告する．分類を表 1 に示す．

表 1. veraPDF 失敗ルールの帰属

| 条項 | 失敗数 | 内容 | 帰属 |
|---|---|---|---|
| 7.3-1 | 0（解消） | Figure タグの代替テキスト欠落 | テンプレ側．#197 で解消 |
| 7.1-8 | 0（解消） | Catalog の Metadata 鍵欠落 | テンプレ側．#198 で解消 |
| 5-1 | 1 | PDF/UA 版数宣言の欠落 | 意図した非宣言 |
| 7.1-3 | 349 | Artifact でも実コンテンツでもない内容 | 内訳確定（Issue #203）．上流由来 315・テンプレ側で検討 34 |
| 7.18.5-2 | 176 | リンク注釈の Contents（代替説明）欠落 | 上流由来 |
| 7.18.1-2 | 176 | 注釈が構造ツリーへ未接続 | 上流由来 |
| 7.2-20 | 57 | LI 直下に Lbl・LBody 以外の要素 | 上流由来 |

## テンプレ側で解消した 2 ルール

- 7.3-1 は `figure` ラッパーと表紙の装飾画像が原因だった．
  rehype 前処理（`scripts/label-figures.mjs`）で解消した（#197）．
- 7.1-8 は XMP メタデータの埋め込みで解消した（#198）．
  `scripts/add-pdf-metadata.mjs` がビルドの最終段で書き込む．

## 意図した非宣言の 1 ルール

条項 5-1 は「pdfuaid:part による版数宣言が無い」という指摘である．
上流由来の非準拠が残る現状で宣言すると，事実と異なる適合表明になる．
このため書かない判断とした（#198）．判断は
[タグ付き PDF 生成 spec](../spec/pdf-tagging.md) が明記する．
残る 4 ルールが解消したときに宣言を再検討する．

## 上流由来の 3 ルールと内訳を確定した 1 ルール

リンク注釈の 2 ルールとリスト構造の 1 ルールは，原稿・テンプレの
HTML に制御点が無い．タグ付けは Vivliostyle CLI 内部の
Chromium（print-to-PDF）が行い，その変換の限界に由来する．
7.1-3 は当初「帰属未確定」としたが，Issue #203 で全数の内訳を確定した．

### 7.1-3: 未マークの内容（349 件・内訳確定）

Issue #203 で内容ストリームを解析し，全 349 件を特定した．
CI レポート（run 33128813282）と同一の PDF を対象に，
マーク外の描画オペレータを数えると総計が 349 件で一致する．
テキストは ToUnicode で復号し，パスは CTM を追跡した実位置から
同定した．内訳を表 2 に示す．

表 2. 7.1-3 の内訳（349 件）

| 種別 | 件数 | 発生源 |
|---|---|---|
| 数式のグリフ | 179 | MathJax の視覚出力（aria-hidden） |
| 箇条書きマーカー（パス） | 35 | ul の点・輪郭（::marker 相当の描画） |
| aria-hidden の figcaption | 34 | VFM 生成キャプションの本文（後述） |
| 見出し番号チップ | 24 | h2 装飾（左端の 53x25pt の帯） |
| 箇条書きマーカー（文字） | 24 | ol の「1.」「2.」等 |
| 見出しの装飾帯 | 14 | 小見出しの下線帯（7〜8pt 高） |
| 行番号ガター | 14 | コードブロック 7 個の帯と右罫線 |
| 表紙の背景 SVG | 7 | presentation 化した装飾画像の描画 |
| 数式の罫線 | 6 | 分数線・ルート記号の線 |
| 章扉の枠・帯 | 7 | まとめ枠 3・トピック帯 4 |
| 枠アイコン・枠線ほか | 5 | コラム等の線画 3・枠線 1・画像 1 |

機序は 1 つに集約できる．この PDF では BDC 1585 個のうち
Artifact 指定が 0 個である．Chromium の print-to-PDF は装飾を
Artifact として刻まない．構造ツリー外の描画（aria-hidden・
presentation・マーカー・疑似要素の装飾）はすべて未マークに落ちる．

前回レポート（342 件）との差 7 件は，#197 で表紙画像を
presentation 化して Figure タグから外れた分と一致する．

帰属は次のとおり確定する．

- **上流由来（315 件）**．数式・マーカー・見出し装飾・ガター・
  章扉・表紙・アイコン類．いずれも装飾または aria-hidden であり，
  本来は Artifact になるべき内容である．HTML 側に制御点は無く，
  Chromium が Artifact を出力しないことに由来する．
- **テンプレ側で検討（34 件）**．VFM が生成する figcaption は
  `aria-hidden="true"` を持ち，本文の描画が未マークになる．
  キャプションの文字列は #197 の前処理が figure の `/Alt` へ
  写しており，読み上げは確保済みである．aria-hidden を外して
  タグ付き本文へ戻す選択はテンプレ側にあるが，`/Alt` との
  二重読みという交換条件を伴う．Issue #205 で検討する．

### 7.18.5-2・7.18.1-2: リンク注釈（各 176 件）

リンク注釈に `/Contents`（代替説明）が無く，構造ツリーの Link
要素へも接続されていない．件数が一致するため同じ注釈群である．
目次・索引・本文の URL リンクが該当する．
Chromium のタグ付けがこれらを生成しないことに由来する．

### 7.2-20: リスト構造（57 件）

LI 構造要素の直下に Lbl・LBody 以外の要素が置かれる．
Chromium のリストのタグ付けに由来する．

## 件数は環境で揺れる

7.1-3 の件数は同じ原稿でも実行環境で揺れる（324〜349 件を観測）．
チェック総数も local と CI で一致しない（738〜759 件）．
レンダラ（Chromium）の版差によるとみられる．
件数の増減を追うときは同一環境の前後で比べること．
veraPDF の JSON 構造を実出力から採った経緯は
[2026-08-27 のノート](2026-08-27-verapdf-ci-report.md) を参照．

## 上流の既知 Issue と報告要否

確認した既知 Issue は次のとおり．

- [vivliostyle.js#1555](https://github.com/vivliostyle/vivliostyle.js/issues/1555)（クローズ済み）．
  Adobe Reader の読み上げが失敗する報告．
- [vivliostyle.js#1561](https://github.com/vivliostyle/vivliostyle.js/issues/1561)（オープン）．
  ページマージンボックス（柱・ノンブル）へ
  `aria-hidden` を付けるかの議論．ヘッダ・フッタの Artifact 化に
  対応する論点であり，7.1-3 と地続きである．
- [vivliostyle-cli#539](https://github.com/vivliostyle/vivliostyle-cli/issues/539)（クローズ済み）．
  タグ付き PDF が出ない報告．v8.16.1 で修正済み．
- リンク注釈（7.18.x）とリスト構造（7.2-20）を個別に扱う Issue は，
  両リポジトリに見当たらなかった．

報告は当面見送る．根拠はルールごとに分けて書く．

- リンク注釈（7.18.5-2・7.18.1-2）とリスト構造（7.2-20）は
  機序が明確である．タグ付けは Vivliostyle のコードでなく，
  Chromium の print-to-PDF が担う．
  Vivliostyle への起票は解決経路とならず，
  Chromium 側の改善を待つ構図になる．
- 7.1-3 の上流由来分（315 件）は，Artifact を出力しない
  Chromium の挙動 1 つに集約される（Issue #203）．
  Vivliostyle 側の近い受け皿は #1561 であり，重複起票を避ける．
- 7.1-3 のテンプレ側で検討する 34 件は，Issue #205 が扱う．

再検討のトリガは次の 2 つとする．

- Chromium のタグ付き PDF 生成が改善したとき．Artifact の出力と
  Link 要素への注釈接続が対象である．
- #1561 が動き，マージンボックスの扱いが決まったとき．
