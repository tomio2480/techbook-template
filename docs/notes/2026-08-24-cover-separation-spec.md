## Issue の前提が実測と食い違っていた

Issue 本文は「表紙を抜くと本文は 62 ページとなり 4 の倍数を外れる」と書いていた．
派生リポジトリの実測では，表紙の有無によらず 64 ページであった．
表紙 2 ページを抜くと後続の面がずれる．
改丁で入る MEMO ページが 2 ページ増え，差を埋める．

見立てを書いた本人と実測した本人は同じである．
起票は 2026-08-17 である．実測は 2026-08-20 であり，3 日で前提が古びた．
還元では，起票時の記述より先方が残した実測記録を先に読む．

面付けの再計画そのものは要る．
総ページ数が偶然一致しただけであり，MEMO ページの位置と枚数は変わる．

## 選択肢を足すと既存の言い切りが矛盾になる

「表紙を含めない」という選択肢を足した．
既存の spec は裏表紙を無条件に本文 PDF の最終ページと書いていた．
該当は 3 か所である．

表 2. 無条件の言い切りが残っていた箇所

| 場所 | 記述 |
|---|---|
| `print-layout.md` の面付けの要件 | 不足分は調整ページで埋め，裏表紙を最終ページに保つ |
| `cover.md` の用語集 | 裏表紙（back-cover）は本文 PDF の最終ページ |
| `isdn.md` の要件 | 裏表紙ページを本文 PDF の最終ページとして追加する |

Codex のレビューは `cover.md` と `isdn.md` を指摘した．
`print-layout.md` の 1 件は指摘に含まれず，同じ形として自分で拾った．
指摘された分だけ直すと，同じ矛盾が PR の中へ残る．

書き足した受け入れ条件にも同じ誤りがあった．
「最終ページは奥付になる」と言い切ったが，端数 1 ページが末尾へ残りうる．
同種の既存条件は，端数 1 ページを許す形で書いてあった．
新しい条件を足すときは，同じ主題の既存条件と形をそろえる．

書き分けの方針は，出力ごとに spec を分ける形にしなかった．
指定の出所を `print-layout.md` の 1 か所へ置き，他の spec はそれを参照する．
面の指定を `config/book.yaml` へ寄せた既存の方針にそろえるためである．

## CI の緑は textlint の 0 件を意味しない

修正の 1 巡目で `no-doubled-joshi` を 1 件踏んだ．
Markdown Lint のジョブは pass と表示された．
`filter-mode` が `added` であり `fail-on-error` が false のためである．
lint summary のコメントに件数が出る．ジョブの色ではなくこの表を読む．

## 還元では上流の方が新しいことがある

先方の `scripts/` は本テンプレートより古い．
`tabLabelFor`・`print.section_tabs`・`check-index.mjs` を持たない．
`build-print.mjs` の差分は 60 行あった．表紙に関わる部分は一部である．
そのまま持ち込むと，上流で直した箇所が巻き戻る．
還元では差分の向きを 1 か所ずつ確かめる．
