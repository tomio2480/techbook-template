## 背景

執筆規律は図表キャプションを体言止めとし，句点を付けないと定めている．
一方 `ja-no-mixed-period` はキャプションと地の文を区別できず，
句点の無いキャプションを「文末が『．』で終わっていません」と指摘する．

本リポジトリはこの食い違いを抱えたまま運用していた．
既存キャプション 17 件はすべて末尾へ「．」を付けており，
規律どおりに書くと指摘され，規律に反して書くと通る状態だった．
PR #115 で句点の無いキャプションを書いた時点で，マージの障害として表に出た．

## クローズ済み Issue の見直しトリガ

上流 #57 が同じ問題をすでに扱っていた．結論は「中央では対応しない」である．
2026-07-08 の時点で，中央設定を使う caller はいずれも句点付きの慣例で運用しており，
実害が無い状態での中央変更は過剰設計と判断していた．

同 Issue は見直しトリガを 3 つ明記して閉じていた．

- 中央設定を採用する caller が句点なしのキャプションを要望したとき．
- techbook 側が将来 lint 導入を検討したとき．
- 上流ルールにノード種別の除外機能が入ったとき．

本リポジトリが lint を導入し，PR #115 で最初の 2 つが同時に引かれた．
クローズ済みだからと切り離さず，まず #57 を読み直したことで，
過去に検討済みの案を作り直さずに済んだ．

## 手段は当時と変わっていた

上流 #57 が暫定策として挙げていた案 C は `.textlintrc.json` の `overrides` で
ファイル単位に無効化する形だった．これは現在使えない．
textlint 15.6.0 が `overrides` を実装しておらず，書いても効かない（上流 #85）．

代わりに，#57 のクローズ後に入った `.textlint-allowlist.yml` を使った．
行単位で外せるため，ファイルごと止める案 C より範囲が狭い．

表 1. キャプション除外の手段と可否

| 手段 | 可否 | 理由 |
|---|---|---|
| ルールのオプション | 不可 | ノード種別を追加除外する項目が無い |
| `.textlintrc.json` の `overrides` | 不可 | textlint 15.6.0 が読まない（上流 #85） |
| `.textlint-allowlist.yml` | 可 | 行単位で外せる．#57 の時点には無かった |

古い Issue の結論をそのまま適用せず，前提が変わっていないかを確かめる．
本件では手段そのものが増えており，当時の暫定案より良い形が取れた．

## 規律と実体のどちらへ寄せるか

選択肢は 2 つあった．該当 1 行へ「．」を足して現状へ合わせるか，
除外を用意して既存 17 件から「．」を落とし規律へ合わせるかである．

後者を選んだ．前者は 1 文字で済むが，規律と実体の食い違いが残り，
次にキャプションを書く者が同じ判断を繰り返す．
除外の理由をコメントで残せば，判断は 1 度で終わる．

行ごと除外になるため，キャプション内の読点や表記ゆれの検査も止まる．
奥付の発行履歴で同じ割り切りをしており，短い体言止めなら実害は小さいと見た．

## 手元の件数が CI と食い違う 2 つの原因

CI の Lint summary は 48 件を出し，手元の再現は 101 件を出した．
指摘が増えたわけではなく，数える対象が違っていた．

- CI は `count-lint-findings.py --diff-files-from` で
  PR の変更ファイルへ絞って数える．全 Markdown の件数と直接は比べられない．
- Windows の作業ツリーは `core.autocrlf=true` で CRLF になる．
  LF で checkout する CI と改行が違い，件数がずれる．

`git archive` で書き出した木を LF へ直し，変更ファイルへ絞って数え直すと
48 件で一致した．全 Markdown では 96 件である．

表 2. 条件ごとの textlint 指摘件数（LF 正規化後・全 Markdown）

| 条件 | 全指摘 | うち `ja-no-mixed-period` |
|---|---|---|
| 変更前 | 96 | 7 |
| 変更後 | 96 | 7 |
| 変更後・allow 行を抜く | 113 | 24 |

差分 17 件はすべて句点を落としたキャプションであり，狙った範囲と一致する．
件数が合わないときは，まず対象範囲と改行を疑う．

## 原稿側は同じ手が使えない

原稿（`src/chapters/`）のキャプションは番号を `theme.css` が自動で付ける．
`README.md` の規約どおり表の直前へ本文だけを 1 行書くため，
行頭に「表 N.」の接頭辞が無い．体言止めの地の文と機械的に区別できず，
正規表現では狙えない．

残る 7 件のうち 2 件は末尾が「:」のコード導入文であり，キャプションですらない．
同じ「短い体言止めの段落」という形に紛れている．
本件の対象から外し，Issue #118 で方針を決める．
