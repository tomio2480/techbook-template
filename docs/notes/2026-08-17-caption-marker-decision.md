# 原稿キャプションを目印コメントで外す判断

原稿側の表キャプションが `ja-no-mixed-period` に検出される問題を解いた記録である．
いったん決めた「原稿にも接頭辞を書く」方針を，着手時の調査で取り下げた経緯を残す．
対象は Issue #118 と PR #126 である．

## 背景

`docs/` のキャプションは接頭辞（`表 1. …`）を持つ．
このため `.textlint-allowlist.yml` の正規表現で外せる（Issue #116・PR #117）．
原稿側は `theme.css` が番号を付けるため接頭辞を持たず，同じ手を使えない．
短い体言止めの段落は地の文と機械的に区別できず，7 件が検出されていた．

Issue #118 では，原稿にも接頭辞を書いて `docs/` と形をそろえる方針を決めていた．
同時に「自動採番との二重化を着手時に解く」ことを条件として残していた．
その条件を調べた結果，方針そのものを取り下げる判断に至った．

## 接頭辞方式が成り立たない理由

紙面は `表1.-1: ` を `::before` で刷る．
原稿へ `表 4. 部品表` と書くと `表1.-1: 表 4. 部品表` になる．
併用はできず，接頭辞を採るなら CSS の採番を止める前提となる．

止める影響は表 1 のとおりである．

表 1. 採番を止めた場合に失うもの

| 対象 | 内容 |
|---|---|
| 規則の数 | 表・図それぞれ 4 階層 × 通常章／付録の計 16 規則 |
| 付録の形式 | `表A.1.-1` のアルファベット採番．手書きでは維持が難しい |
| 数式との整合 | 数式番号は原稿へ書けず CSS に残り，採番の出所が割れる |
| 図の代替テキスト | VFM は `figcaption` を alt の複製として作るため番号が混ざる |

図のキャプションは `<figcaption aria-hidden="true">` として出力される．
読み上げは alt が担うため，そこへ番号を書くと本文の情報が濁る．
なお本件の検出 7 件に図は含まれず，表キャプション 5 件と，
末尾が「:」のコード・数式の導入文 2 件であった．

## 目印コメントは採番を壊さない

キャプション段落を `textlint-disable` と `textlint-enable` で挟む形を採った．
懸念は，段落と表のあいだへコメントが入ることで
`p:has(+ table)` の隣接判定が崩れ，採番と体裁が失われることであった．

VFM の出力で確かめたところ，コメントはコメントノードとして残る．
要素ではないため隣接兄弟の判定に関与しない．

```html
<p>部品表</p><!-- textlint-enable … --><table>
```

紙面でも `表1.2.-1: 部品表` から `表A.1.-1: よく使われる数学記号の例` まで，
付録のアルファベット採番を含めて維持されることを確認した．

## disable-next-line は効かない

1 行で済ませる `textlint-disable-next-line` を試したが指摘は消えなかった．
コメントの直後に置いた場合も，空行を挟んだ場合も同じである．
`textlint-filter-rule-comments` 1.3.0 の挙動であり，挟む形だけが機能する．
README にも「使わない」と明記した．

## 検証の手順

textlint は中央の `scripts/generate-textlint-runtime.py` を使った．
runtime config を生成し，依存を CI と同じ版へ固定して実行した．
LF へ正規化した木に対し，該当 7 件が 0 件になることを確かめた．

このとき `--no-textlintrc` を付けると，rules を読まず
`No rules found` で素通りする．`--config` だけを渡すこと．
指摘が 0 件になったのか，検査自体が動いていないのかを取り違えやすい．

紙面の確認は `@opendataloader/pdf` で PDF からテキストを抜き，
キャプションの番号を文字列として突き合わせた．
画面の目視より速く，付録の採番まで一度に確かめられる．

## docs 側との違い

原稿と `docs/` で扱いが分かれる．表 2 に整理する．

表 2. キャプションの指摘を外す手段の対応

| 対象 | 接頭辞 | 番号の出所 | 指摘を外す手段 |
|---|---|---|---|
| `docs/` | 書く | 手書き | `.textlint-allowlist.yml` の正規表現 |
| 原稿 | 書かない | `theme.css` の採番 | `textlint-disable` と `textlint-enable` |

分かれる理由は自動採番の有無である．
`docs/` は採番を持たないため，接頭辞と番号が二重にならない．

## 残る課題

- キャプションを段落の種別として判別する手段は，textlint 側に無いままである．
  上流 `tomio2480/github-workflows#57` の見送り理由は変わっていない．
- 派生リポジトリでも同じ形の指摘が出る．README の記述で手当てするが，
  執筆時にコメントを書き忘れると `filter-mode: added` で表に出る．
- 画像とキャプションを 1 対 1 とする規律は維持する．
  接頭辞の規律だけを，自動採番を持つ原稿側から外した．
