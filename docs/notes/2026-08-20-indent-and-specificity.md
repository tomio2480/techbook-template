# 誌面の既定を変える 2 件で踏んだ落とし穴

段落の字下げ（Issue #132）と数式の行末禁則（Issue #134）を片づけた記録である．
どちらも Issue に対処案があったが，そのまま当てると外れる部分を含んでいた．
CSS の詳細度・マージン相殺・前後の突き合わせで見つけた食い違いを残す．

## 背景

派生リポジトリの著者レビューから還元された Issue のうち，2 件を片づけた．
#134 は開き括弧の直後に置いた数式で行末禁則が破れる件である．
真因の切り分けは `2026-08-18-math-kinsoku.md` へ別に残した．
本稿は #132（全段落を 1 字下げる）で踏んだ落とし穴を中心に書く．

## 詳細度で足をすくわれた

Issue の提案は，枠の最終要素の下アキを次の形で消すものだった．

```css
.caution > *:last-child,
.column > *:last-child,
.tips > *:last-child,
.chapter-recap > *:last-child { margin-bottom: 0; }
```

本テンプレートでは，この形のままだと足りない．
枠の中の段落には `.tips p:not(.tips-title)` のような指定が既にあり，
詳細度で負けるためである．

表 1. 枠まわりのセレクタと詳細度

| セレクタ | 詳細度 | 効く相手 |
|---|---|---|
| `.tips p:not(.tips-title)` | (0,2,1) | 枠の中の段落 |
| `.tips p:last-child` | (0,2,1) | 枠の最後の段落 |
| `.tips > *:last-child` | (0,2,0) | 枠の最後の要素 |
| `.caution > ul` | (0,1,1) | 枠の中のリスト |

`*` は詳細度を上げない．`:last-child` は擬似クラスとして 1 つぶん数える．
提案の形だけを入れると，リストや図の下アキは消える一方，
段落の下アキは 6pt 残る．見た目が枠ごとにそろわない．

要素を問わない指定と段落の指定を併記し，枠ごとの指定より後ろへ置いた．
同じ詳細度どうしは後ろが勝つためである．

## 縮み幅が見立ての 3 分の 1 だった

リストで終わる枠の高さは 6pt 縮むと見ていた．`ul` の下アキがその値だからである．
実測は 61.7pt から 59.7pt であり，縮みは 2pt だった．

原因はマージン相殺である．`li` は下アキを 4pt 持つ．
`ul` には下の余白と罫線が無いため，最後の `li` の下アキは `ul` の下アキと相殺する．
相殺後は大きいほうが残るため，6pt を消しても 4pt が残る．

見立てと実測の差はここでしか出ない．数値で確かめないと，
指定が効いていないのか，効いたうえで別の余白が残っているのか区別できない．

## 前後の PDF を行単位で突き合わせる

字下げの既定を変える指定は，本文のほぼ全段落へ当たる．
最小構成では影響の広さを測れないため，本番と同じ経路で前後を作って比べた．

1. 変更後の `theme.css` を退避し，`git checkout` で変更前へ戻す．
2. `npm run build` で変更前の PDF を作る（1 回およそ 60 秒）．
3. 退避した `theme.css` を書き戻し，もう一度 `npm run build` を回す．
4. PyMuPDF で両方の行を復元し，行頭の x 座標を突き合わせる．

結果は次のとおりである．本文の段落 36 箇所が 51pt から 61pt へ動いた（1em は 10pt）．
枠の中の 9pt の段落は 1 箇所も動かない．各枠が `text-indent: 0` を明示しているためである．
総ページ数は 29 のまま変わらない．

突き合わせには落とし穴がある．同じ文字列の行が複数あると，相手を取り違える．
柱（ページ上部の見出し）と章見出しは同じ文字列になるため，
章見出しが 164pt 動いたように見えた．
実際はどちらも動いておらず，比較の相手が柱になっていただけである．
疑わしい行は，ページを指定してスパンの座標を直接見ると切り分けられる．

## 並行して進む main への注意

本セッションと並行して，別のセッションが PR #142 を `main` へ入れた．
PR の CI は，その PR を作った時点の `main` に対して走る．
あとから別の変更が入ると，統合後の状態は誰も確かめていないまま残る．

マージ後の `main` で `npm test`（394 件成功）と `npm run build:print`（全 36 ページ）を
回して確かめた．#142 は表紙と紙面の塗り足しを触っており，
本セッションの本文まわりの変更とは当たる場所が違うと分かった．
